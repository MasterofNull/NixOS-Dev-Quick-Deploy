# CI/CD state-of-the-art for AI-agent repositories, compared with our harness

Date: 2026-11-04. Analyst role, read-only. Evidence: workflow files fetched 2026-11-04 into
`.agents/delegation/outputs/cicd-corpus-20261104/` (19 repos, 368 non-empty YAML workflow files).
Citation form is `owner/repo:<file>:<line>` as stored in the corpus. Our files are cited by repo-relative path.
The Gemini lead log was used only as a pointer for what to look for; nothing here cites it.

Corpus caveats (they limit what can be claimed):
- The corpus holds `.github/workflows/*` only. Repository rulesets, `dependabot.yml`, `CODEOWNERS`, helper scripts
  under `.github/scripts/`, composite actions and test sources are NOT in it. Anything that depends on them is under "Not verified".
- 37 zero-byte or newline-named junk files exist in the corpus (for example `Aider-AI_aider/check_pypi_version.yml`
  has a sibling with a listing as its name). They carry no content and do not change any count below.
- Prevalence is by regex over the corpus, then spot-checked by reading the matching file. "n/19" means repos with at least one hit unless stated.

## 1. Summary

1. Shared practice in the better-run repos: SHA-pinned actions (10/19 near-fully pinned, 14/19 at least partly), `permissions:` everywhere (19/19, top-level in 234/368 files), `concurrency` cancel (17/19), path or affected-package filters (16/19 `paths:`), job timeouts (13/19).
2. The strongest merge-gating design is a single version-controlled aggregator job (`if: always()` plus `needs:`) that the ruleset requires: openai/codex:blocking-ci.yml:48, langchain-ai/langgraph:ci.yml:173, zed-industries/zed:run_tests.yml:1007, google-gemini/gemini-cli:ci.yml:487.
3. Cost control for scarce minutes is explicit in the leaders: fast PR tier vs full post-merge tier (openai/codex:README.md:5-33), label-gated heavy Nix build (zed-industries/zed:nix_build.yml:16), mock E2E only on main and release PRs (All-Hands-AI/OpenHands:mock-llm-e2e.yml:3-10), eval runs only on prompt/tool path changes behind an approval environment (google-gemini/gemini-cli:eval-pr.yml:5-14,92).
4. Agent-specific testing is thin in public workflows. Only OpenHands has a mock-LLM E2E tier (1/19). Live-model tests are fork-skipped and key-gated (goose, claude-code-action, OpenHands, langgraph). Conformance is protocol-level (goose MCP, sigstore) with an expected-failures baseline, and model tool-call sweeps are scheduled and deliberately non-gating (block/goose:model-toolcall-conformance.yml:3-7).
5. AI review/triage bots are common for issues (6/19) but AI PR review appears in only 1/19 (anthropics/claude-code-action:claude-review.yml:25). None of the visible workflows lets an AI check replace human merge authority. Human gates are environments (gemini `eval-gate`, cline `PublishNPM`) and separation rules (OpenHands verify-skill-isolation).
6. Our harness is already ahead on: SHA pinning (13/13), top-level `permissions` (13/13), local-CI parity (`ci-checks.json`, `ci-merge-parity.sh`), secret scanning (gitleaks, blocking), Nix closure scan with SBOM, and a head-bound independent-review check.
7. Biggest gaps: no `concurrency` on 12 of 13 workflows, `timeout-minutes` on 2 of 13 files, masked failures (`|| true`, `continue-on-error`), duplicated jobs (shellcheck x3, gitleaks x2, repo-structure-lint x2, Nix toplevel built twice), no workflow linter (actionlint/zizmor), no aggregator required-check job, no updater for pinned SHAs.
8. Integrity gaps specific to an AI-lane repo: nothing stops a PR from editing gate code together with product code (OpenHands solves this: All-Hands-AI/OpenHands:verify-skill-isolation.yml:3-22), and release publishing uses a static npm token with no provenance (`.github/workflows/harness-sdk-release.yml:122-149`).
9. Most recommendations are subtractive or hygiene (freeze-allowed); mock-LLM E2E, conformance sweeps, eval gates, attestation and tiered CI policy are post-freeze features.

## 3. Agent-specific practices worth special attention

### 3.1 Mock-LLM E2E (OpenHands only)
- Two workflows run the same Playwright specs against a mock LLM: npm path (All-Hands-AI/OpenHands:mock-llm-e2e.yml) and Docker image path (All-Hands-AI/OpenHands:mock-llm-docker-e2e.yml:3-30, triggered by `workflow_run` after the image workflow completes on main).
- The mock is an OpenAI-compatible server (`/v1/chat/completions`, probed at mock-llm-e2e.yml:100-110) built from the SDK package pinned in `config/defaults.json` (mock-llm-e2e.yml:36-40,74-79). The mock is itself tested first by pytest (`mock-llm-e2e.yml:91-92`), then started once as a probe (`:94-111`), then the E2E runs.
- Trigger economy: push to main, the release-please PR only (`paths: .release-please-manifest.json`), and manual dispatch (mock-llm-e2e.yml:3-10). Not on every PR.
- Robustness: Playwright is run in the background with a done-marker reporter and a pass marker, so a hung webServer teardown cannot fail a green run (`mock-llm-e2e.yml:124-170`). A global timeout of 20 minutes is set with job timeout 30 (`:26,120`).
- Live tier is separate: `live-e2e` runs only on dispatch or push to main (OpenHands ci.yml:97-100), uses a cheap model (`ci.yml:111-112` shows a Haiku-class default), serializes without cancel (`ci.yml:102-105`), skips when no key is configured (`ci.yml:288`), skips fork PRs, and records video evidence plus a PR comment report (`ci.yml:300,321,467`). It is non-blocking by design: the test step is `set +e` and records an exit code instead of failing (`ci.yml:282`; result computed at `:443`).
- What others do instead of mocking (workflows only show guards, not fixtures): goose runs live-provider tests with a fork/dependabot guard (block/goose:pr-smoke-test.yml:16-24); langgraph skips integration steps when the key secret is empty (langchain-ai/langgraph:_integration_test.yml:35,63); continue passes `IGNORE_API_KEY_TESTS` computed from whether LLM-related files changed (continuedev/continue:pr-checks.yaml:57-62,72-86); autogen runs its OpenAI test only on main inside a protected environment (microsoft/autogen:dotnet-build.yml:219-225).

### 3.2 Conformance suites
- Protocol conformance with a baseline of known failures: goose builds a driver binary, then runs a matrix of MCP spec versions x conformance-suite versions, each with its own `expected-failures-<spec>-<suite>.yaml` (block/goose:mcp-conformance.yml:50-66,78-90). It runs on PR, push, `merge_group` and dispatch (`:3-11`). This is a ratchet: new failures break, known ones are documented.
- Model tool-call conformance, deliberately non-gating: block/goose:model-toolcall-conformance.yml:3-7 states why (third-party models over the network; a failure usually means the provider regressed). Daily 03:00 UTC cron plus dispatch inputs for model count or explicit list (`:9-23`), 60 minute timeout (`:34`), repository guard because only upstream holds secrets (`:32-33`), per-model logs kept 14 days (`:71-77`).
- Cross-implementation conformance with failure issue: sigstore/cosign:conformance-nightly.yml:46-48 runs the shared suite nightly and opens one deduplicated issue on failure (`:52-80`), cc'ing owners.
- Behavioral claim tests for an agent action: anthropics/claude-code-action:test-structured-output.yml, test-settings.yml, test-mcp-servers.yml pin the model (`ANTHROPIC_MODEL`, lines 15-17), skip forks (lines 24, 88), and write a pass/fail table to the step summary (`test-structured-output.yml:309-320`, "Fast, deterministic tests using explicit prompts" at :313). Real model, explicit prompts, exact expected values.

### 3.3 Eval gates (Gemini CLI is the reference)
- PR eval runs only when "steering" files change: `packages/core/src/prompts/**`, `tools/**`, `agents/**`, `evals/**`, excluding tests (google-gemini/gemini-cli:eval-pr.yml:5-14). Detection runs a trusted script from main and fetches the fork head without checking it out (`:34-52`).
- A maintainer must approve the `eval-gate` environment before fork code runs (`:92`; instructions posted as a PR comment `:58`, comment removed after approval `:108`). Concurrency cancel is justified in a comment as "saves tokens" (`:15-17`).
- The regression check script posts a report and "consider adding evals" guidance when steering files change without eval changes (`eval-pr.yml:135,153,167`); model list is a single env var (`:96`).
- Nightly: matrix of 6 models x 3 attempts for the `USUALLY_PASSING` tier, `continue-on-error`, framework-level retries disabled in favor of helper-level retry (google-gemini/gemini-cli:evals-nightly.yml:32-54,79), then an aggregate job renders a step summary (`:102,118`). Separate `perf-nightly.yml` and `memory-nightly.yml` run at 03:00 and 02:00 UTC.
- LangGraph's variant is plain performance: baseline benchmark cached on main (langchain-ai/langgraph:baseline.yml:34-40), PR run restores the cache with `fail-on-cache-miss` and uses `pyperf compare_to`, reporting by annotation only (bench.yml:26-34,41-48).

### 3.4 AI review and autofix
- Review: claude-code-action reviews its own PRs with the action itself, only on `opened`, same-repo only, restricted tool set, Workload Identity Federation instead of an API key (anthropics/claude-code-action:claude-review.yml:3-5,9,16-31,35-40). Org-level guards: a PR touching `allowed_non_write_users` triggers a warning comment (non-write-users-check.yml:24-44), and a CI check fails any workflow job that calls Claude without required security settings (workflow-hardening.yml:1-23).
- Hardening conventions repeated across Anthropic repos: egress-firewall runner (claude-dedupe-issues.yml:15-18), per-run script caps `CLAUDE_CODE_SCRIPT_CAPS` (anthropics/claude-code:claude-issue-triage.yml:36), `--disallowedTools` for write/web tools (`:48-53`), pinned model, `timeout-minutes` (`claude-dedupe-issues.yml:19`), OIDC-minted short-lived credentials (`:21-23`).
- Codex issue dedupe: `openai/codex-action` with `sandbox: read-only`, `safety-strategy: drop-sudo`, structured `output-schema` with `additionalProperties: false`, two passes (all issues, then normalize) (openai/codex:issue-deduplicator.yml:61-100,205).
- Autofix: zed dispatches a fix workflow on demand, builds a patch artifact in an unprivileged job and applies it in a separate `commit_changes` job authenticated as an app (zed-industries/zed:autofix_pr.yml:3-16,73,82,95,102,127). Gemini's bot opens PRs only when `enable_prs` is set (default false) (google-gemini/gemini-cli:gemini-cli-bot-brain.yml:26-30). Continue's auto-fix-failed-tests ships turned off (continuedev/continue:auto-fix-failed-tests.yml:18-19), an honest dormant state.
- Autonomous merge is always scoped: opencode's bot may merge only if the branch changes exactly `nix/hashes.json` and the file validates (sst/opencode:check-bot-scope.yml:3-6,44-60), goose auto-merges Dependabot patch/minor only (block/goose:dependabot-auto-merge.yml:20-34).
- Separation of verifier and author: OpenHands forbids changing verification skills in the same PR as product code (All-Hands-AI/OpenHands:verify-skill-isolation.yml:3-22). This is the closest analogue to our Rule on non-self-review.

## 4. Top 10 recommendations for our harness (ranked by value / effort)

Classification key: INTEGRITY = security or gate-soundness fix, allowed during the feature freeze. HYGIENE = removes waste or masked failure, no new capability, allowed. FEATURE = new capability, post-freeze.

### 1. Gate-file isolation check (INTEGRITY, effort S-M)
- Evidence: All-Hands-AI/OpenHands:verify-skill-isolation.yml:3-22; sst/opencode:check-bot-scope.yml:3-6,44-50; anthropics/claude-code-action:non-write-users-check.yml:4-5,24-44.
- Gap: `check-review-disposition.py` binds the review to the head sha, but one PR can change the checker, `config/ci-checks.json`, `scripts/governance/tier0.d/*` and `.github/workflows/*` together with product code. All lanes share one GitHub account and `CODEOWNERS` has one owner (`.github/CODEOWNERS:2,19`), so no reviewer routing helps.
- Change: new required check that fails (or demands a stronger `Review-Receipt` class) when a diff touches gate paths and also touches anything else. Fits as a manifest entry.
- Files: `config/ci-checks.json` (new check), new `scripts/governance/check-gate-isolation.py`, one step in `.github/workflows/review-disposition.yml`.
- Risk: legitimate combined changes (renaming a script and its caller) need a split or an override label; keep override owner-only and logged.

### 2. Workflow linter in the manifest (INTEGRITY, effort M)
- Evidence: zed-industries/zed:run_tests.yml:808,823-825; anthropics/claude-code:workflow-hardening.yml:22-23; `# zizmor: ignore` in zed-industries/zed:community_pr_board.yml:15 and ossf/scorecard:osps-baseline-publish.yml:66.
- Change: one manifest check running actionlint and zizmor (reach via `aq-tool`, pinned by Nix, not downloaded from `main` as zed does at run_tests.yml:825), plus a small custom rule set: every `uses:` is 40-hex; top-level `permissions:` present; no `pull_request_target`; no `|| true` or `continue-on-error` without an adjacent `# wr:` register id (Rule 19); `timeout-minutes` on every job.
- Files: `config/ci-checks.json`, new `scripts/governance/check-workflow-hardening.sh` (or `.py`), no workflow change (CI already calls the manifest; `tier0.d/check-ci-manifest-coverage.sh` enforces the mapping). `python-tooling-policy` already lists `.github/workflows/**` in its paths.
- Risk: noisy first run on `test.yml` (894 lines); start in warn mode for the legacy files, fail for new ones.

### 3. Remove masked failures (INTEGRITY, effort S)
- Evidence: ours: `.github/workflows/nix-build.yml:59` (`nix flake check --all-systems || true`), `shellcheck.yml:42` and `validate-shell-scripts.yml:69` (`continue-on-error: true`), `security.yml:59` (comment step, acceptable). Reference: openai/codex:blocking-ci.yml:50-54 (why `always()` and an explicit advisory note instead of silently passing); block/goose:mcp-conformance.yml:56-66 (baseline of expected failures as the alternative to ignoring them).
- Change: either fix, or move to an expected-failures baseline file, or register in `.agent/WORKAROUND-REGISTER.md`. The `nix-build.yml` comment at line 75 already records that a previous `|| true` made the job always pass.
- Files: the three workflows above; `.agent/WORKAROUND-REGISTER.md` if deferred.
- Risk: `nix flake check --all-systems` may fail today on foreign systems; run once locally before flipping.

### 4. `concurrency` with cancel on every workflow (HYGIENE, effort S)
- Evidence: openai/codex:bazel.yml:14 (do not cancel on main); All-Hands-AI/OpenHands:ci.yml:12-22 (per-commit group on push); google-gemini/gemini-cli:eval-pr.yml:15-17.
- Ours: only `.github/workflows/confine-tests.yml:37-39`. A force-push or an agent re-push leaves 12 workflows running to completion on stale commits.
- Files: all `.github/workflows/*.yml` except `confine-tests.yml`. Pattern: `group: ${{ github.workflow }}-${{ github.ref }}`, `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` (never cancel `main` or tag release runs).
- Risk: cancelling `harness-sdk-release.yml` publish jobs; scope the cancel to PR events only.

### 5. `timeout-minutes` on every job (HYGIENE, effort S)
- Evidence: zed-industries/zed (85 occurrences, e.g. add_commented_closed_issue_to_project.yml:21); openai/codex:bazel.yml:21,137; sst/opencode:check-test.yml:292,305,312.
- Ours: 2 of 13 files (`confine-tests.yml:45`, `security.yml:81`); `test.yml` has 17 jobs and none.
- Files: `test.yml`, `tests.yml`, `tests-legacy.yml`, `nix-build.yml` (use 60 to start; the llama-cpp prebuild step is the long pole), `gitleaks.yml`, `shellcheck.yml`, `validate-shell-scripts.yml`, `memory-benchmarks.yml`, `test-coverage.yml`, `harness-sdk-release.yml`, `review-disposition.yml`.
- Risk: a timeout set below a cold-cache Nix build produces false failures; derive from observed durations.

### 6. Deduplicate overlapping jobs, then tier the Nix work (HYGIENE first, FEATURE-policy second; effort S then M)
- Duplicates in ours (verified by reading the files): shellcheck in `test.yml:300`, `shellcheck.yml:27` and `validate-shell-scripts.yml:62`; secret scan in `gitleaks.yml:33` (non-blocking) and `security.yml:184-193` (blocking); `repo-structure-lint` in `tests.yml:13` and `test.yml:13`; the hyperd-ai-dev `toplevel` is built in `nix-build.yml:76` and again in `security.yml:132`, the latter with a 120 minute timeout (`:81`) and no path filter on pull requests (`security.yml:4-7`). `tests-legacy.yml` shares the display name "Tests" with `tests.yml` (purpose not verified).
- Reference design: openai/codex:README.md:5-33 and postmerge-ci.yml:1-8 (fast PR tier; heavy suites after merge, rerunnable by dispatch); zed-industries/zed:nix_build.yml:7-16 (Nix build behind a `run-nix` label).
- Step 1 (allowed now): delete the duplicates, keeping the blocking variant and the manifest as single caller (`config/ci-checks.json` `ci_workflow` mapping must be updated or `check-ci-manifest-coverage` fails). Reuse the toplevel from one job via artifact or let `security.yml` run on schedule and path-filter `nix/**`, `flake.lock`, `hosts/**`.
- Step 2 (post-freeze, owner decision): move the closure vulnerability scan to schedule plus main, keep PR coverage via the local `tier0`/`ci-merge-parity` run. This lowers PR gate coverage, so it is a policy change.
- Risk: dropping a check that is a required status in the ruleset leaves the PR unmergeable; check the ruleset before deleting job names.

### 7. Aggregator "CI required" job (INTEGRITY, effort M; ruleset edit is an owner act)
- Evidence: openai/codex:blocking-ci.yml:11-12,48-73; langchain-ai/langgraph:ci.yml:173-198; zed-industries/zed:run_tests.yml:1007-1063; google-gemini/gemini-cli:ci.yml:487-515.

- Files: `.github/workflows/test.yml` (add final job with `if: always()`), new `scripts/governance/check-ci-results.py`, `config/ci-checks.json` mapping, owner ruleset update (exact command to give the owner at implementation time).
- Risk: the aggregator must fail on `cancelled` and `failure`, not only `failure` (langgraph does this at ci.yml:191).

### 8. Supply-chain fixes in CI and release (INTEGRITY for a-b, FEATURE for c; effort S-M)

### 9. Updater for pinned SHAs, grouped (INTEGRITY/hygiene, effort S)
