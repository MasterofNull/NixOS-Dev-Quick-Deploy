## Deliverable and sequence

1. Pin/license/source inventory; admit only metadata/reference review in the
   existing capability-intake registry. Runtime remains disabled.
2. Catalog upstream agents/skills/commands/hooks/memory/learning/evals/security/
   integrations/orchestration/CI/CD/configuration/observability. Compare each
   concrete feature to local source and live coverage, not file-count marketing.
3. Per-feature verdict: equivalent, stronger-local, partial, missing, unsuitable
   or approval-blocked. Record exact upstream/local evidence, reusable SSOT,
   user-visible value, permissions, dependencies and actual completion proof.
   Documentation present does not imply executable parity or runtime activation.
4. One synthesis/frozen implementation queue, cheapest eligible available lane,
   bounded slices. Reuse native implementations rather than duplicate competing
   lifecycle/authority/memory systems. Nonblocking disagreement goes next slice;
   real safety/authority/data-loss issues block activation with bounded fixes.
5. Implement prioritized genuine gaps with tests and QA/dashboard visibility,
   independent hash-bound review, canonical commit evidence and GitHub CI/CD
   backstop where applicable. Preserve greenfield/brownfield project settings.
6. Local agent/model dogfood and capability/eval validation: baseline and measured
   before/after tool success, correctness, latency/resource cost, graceful suspend/
   recovery, bounded loops and truthful completion. No claimed parity until proved.

## Hard boundaries

Existing FT4-R1 safety corrections/acceptance remain the immediate commit gate;
ECC analysis can run read-only in parallel. No staging mixed unrelated slices,
shared HEAD switches, destructive deletion, secret import, account/ruleset change,
untrusted target execution or system rebuild. Use per-file claims and checkpoints.
Network/write/shell/browser/secret capabilities require pinned dependency/SBOM,
allowlist, sandbox/least privilege, visibility and recovery/rollback disposition
plus acceptance before enabling. Unsafe/inapplicable features are not imported
just to satisfy an exhaustive count; explain and propose safe equivalent outcomes.

implemented gap has real tests, integration/monitoring and truthful independent
acceptance/activation status. Unknown/blocked is visible to owner. Track local

No automatic claims of industry certification or tamper-proof same-user hooks.
