## Validation Evidence
Sequence: lock, then tier0 `--pre-commit` and commit (only when `--commit-msg-file` is given), merge origin/main (a conflict aborts the merge, names the files and stops), independent review of that exact head, push (never forced), PR create if none, `mint` + `publish`, then wait for checks and squash-merge with `--match-head-commit`. The lock covers commit through publish (reviews run tests locally); waiting for CI does not hold it. State: git and GitHub plus `.agents/delegation/outputs/aq-land/<branch>/checkpoint.json` (gitignored, shared across worktrees). The lock file lives beside it and is a kernel flock, so a killed process releases it.
- Resume: every stage derives from remote truth first (ls-remote, `gh pr list`, receipt key in the checkpoint). Tests kill the real aq-land process (SIGKILL from the stub) after push, after PR creation, after publish and after merge; the re-run finishes with one PR, one review, one published receipt, one merge.
- Stale evidence: after each review the loop re-fetches and re-judges. A review counts for a head only if it is that head or the head is a clean automatic merge of main onto it, decided by the same `merge_only_update` the required check uses. A real commit during review forces a second review. A review whose `Reviewed-head-sha` is another head is rejected as lane output.
- Review limits: hard limit 2400 s per lane (1800 s gemini), stall (no growth of the wrapper stdout or the output file it names) 900 s for codex only (gemini and local print nothing until the final answer). Overrides AQ_LAND_REVIEW_TIMEOUT_S, AQ_LAND_STALL_S. The process group is killed. Timeout, stall, quota text with no verdict, no verdict, wrong head, refused codex budget (`--budget-check-only` first, `--force-budget` never passed) fall to the next lane; each is written to the PR body's Review history. A real REQUEST_CHANGES stops. No lane left: one STOP line, exit 1, lock released.
- Lane rules: never the author's lane; local only for diffs up to 30000 bytes (AQ_LAND_LOCAL_MAX_DIFF), with the diff inline; changes under `.github/workflows/review-disposition.yml`, `scripts/governance/`, `.githooks/`, `aq-review-receipt`, `aq-land` never go to local.
- Clutter: no receipt commits on the branch (head unchanged, asserted); documentation-only diffs and receipt files in the diff are refused (`--allow-docs-only` overrides the first).
- Checks: head on the PR must equal the landed head; required list read from branch protection (unreadable: every reported check must pass); a required check not yet reported is pending; an IN_PROGRESS check is judged by its job's conclusion through the Actions jobs API (success counts as passed, in progress stays pending, failure fails); `review-disposition` failures are re-run (max 3) because the check reads live state and the receipt may have been published after the run began.
- Legacy removal: `check-review-disposition.py` drops LEGACY_MAX_PR, schema 1 check, receipt-only head rule and the legacy args of `merge_only_update`; `check()` now requires the receipt loader; a `Review-Receipt:` body line is ignored. `aq-review-receipt mint` always writes schema 2 (`--offbranch` kept as a no-op for old callers); `verify`/`audit` still read old schema 1 files. Canon `delivery-workflow` states landing goes through `aq-land` and documentation ships in the code PR; regenerated into AGENTS.md, .claude/CLAUDE.md and the four .agent files (`canon-compile --check`: no drift).

## Review Round 3 Fixes (verified review findings)
- HIGH, premature merge: `wait_and_merge` always adds `review-disposition` to the required set (also when branch protection is unreadable) and never merges until at least one check has reported for the head and `review-disposition` itself has passed; a check not yet seen counts as pending. It cannot be made optional. Tests: `test_empty_rollup_and_unreadable_protection_never_merges` (waits, then times out on `review-disposition`, no merge) and `test_other_checks_green_without_review_disposition_never_merges`. Existing check tests now carry a passing `review-disposition` in their rollups.
- MEDIUM, corrected body never pushed: `stage_pr` compares the full rendered body with the live body (surrounding whitespace ignored) instead of looking for the `Reviewed-head-sha` line. Root cause also covered a second producer: the resume short-circuit (`settled`) skipped `stage_pr` entirely, so a corrected `--body-file` was dropped on a resumed run; it now calls `stage_pr` (idempotent) before waiting on checks. Test: `test_changed_body_file_is_pushed_on_rerun_and_unchanged_is_not`.
- Docs-only classification: a path is documentation only if it is not code. Code is anything ending `.py .sh .nix .yml .yaml`, anything under `*/scripts/`, and anything tracked with an executable mode, wherever it lives. Tests: `test_code_under_doc_dirs_is_code_but_docs_alone_are_refused` (`.agent/skills/x/scripts/a.py` alone lands; `docs/a.md` alone is refused) and `test_executable_file_under_doc_dirs_is_code`.
- Regression check: the five new tests FAIL against the previous staged `aq-land` and pass on the fixed one.
- Not acted on (checked false): missing `pull-requests: read` permission; `tier0 --ci` running nowhere; forged owner acceptance reaching main; `0 failed` regex matching `10 failed`.

## First Real Use: Lane Problems Found and Fixed
What a first real landing would have hit, from the 2026-11-06 gemini runs:
- Gemini model: the lane passed no `--model`, so the CLI default was used and returned 429 "Individual quota reached" while `gemini-3.8-flash-*` worked. aq-land now passes `--model gemini-3.8-flash-high` (override `AQ_LAND_GEMINI_MODEL`) and retries once on `gemini-3.8-flash-medium` after a quota error; the retry is written to the PR body's Review history. Tests: default and override, one retry with record, quota on both models leaves the lane.
- Wrong tree: a gemini review reported four false findings from the main checkout. The non-local prompt now names the worktree as the only place to read repository files, says the main checkout is out of date and findings from it are wrong, and says not to run test suites. aq-land launches every delegate with cwd set to the worktree. `delegate-to-gemini` does not change directory, so the cwd holds. `delegate-to-codex` did: it `cd`s into a fresh worktree it creates from its own `REPO_ROOT` (or `REPO_ROOT` with `--shared`), never the worktree under review. It now honours `AQ_DELEGATE_CWD` in shared mode, and aq-land passes `--shared` and that variable for codex. Tests: prompt text, gemini cwd, codex args and wrapper source; the codex wrapper itself was not run (a real codex run would spend budget).
- Stall limit vs buffered output: both wrappers pipe through `tee`, so they pass bytes as they arrive, but `gemini -p` prints only its final answer. Completed logs under `.agents/delegation/outputs/gemini-*.log` hold only that answer (no tool or progress text), and reviews ran 2.5 to 13 minutes from file creation to last write (e.g. gemini-20261106-214238-6twr91: 12 min 13 s, 4.5 kB). The data cannot show intermediate writes (mtime is the last write), but a log with no progress text is silent while the model reads files, so a 600 s stall limit could kill a valid 10-minute review. Stall detection is now off for gemini (as for local); the hard limit is 1800 s. `AQ_LAND_STALL_S` only tunes lanes that have a stall limit. Codex exec prints tool activity as it runs and keeps 900 s. Tests: silent gemini hits the hard limit, not a stall; silent codex stalls.
- Not verified live: all of the above against the real CLIs; the Gemini model names were taken from the 2026-11-06 report, not queried.
