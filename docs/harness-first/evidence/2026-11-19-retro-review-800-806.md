## Validation Evidence
Per finding:
- **800-1 (OnBootSec survives next to OnActiveSec)**: `nix/modules/core/timer-stagger.nix` now sets `OnBootSec = mkForce []` plus `OnActiveSec = <hash slot>` on monotonic timers (no `OnCalendar`). An empty list renders no line (nixpkgs `attrsToSection` maps over the list), verified in the rendered unit: `ai-rsi-sweep.timer` has `OnActiveSec=23min`, `OnUnitActiveSec=15min`, no `OnBootSec`. Citations, `man systemd.timer` on this host: "Multiple directives may be combined ... the timer unit will trigger whenever any of the specified timer expressions elapse" (so a kept OnBootSec still fires), and "If a timer configured with OnBootSec= or OnStartupSec= is already in the past when the timer unit is activated, it will immediately elapse ... This is not the case for timers defined in the other directives" (so OnActiveSec, relative to the timer's own activation, is the restart-safe form). Choice: remove rather than offset OnBootSec, because any surviving OnBootSec in the past elapses immediately. The 18 matched monotonic timers (e.g. ai-rsi-sweep, ai-system-state, lore-sync, meta-optimization-analysis) were the ones carrying OnBootSec. Scope is this module's own matched timers only; `mkForce` is on the module's own key for names in its prefix list, hosts opt out via `mySystem.timerStagger.enable`/`prefixes`/`extraNames`.
- **800-2 (calendar jobs gain OnActiveSec)**: calendar-only timers (25 of the matched ones, e.g. ai-optimizer) get no OnActiveSec: `ai-optimizer.timer` renders `OnCalendar=*-*-* 01:10:00`, `RandomizedDelaySec=15min`, `FixedRandomDelay=true`, `Persistent=true` (host-set). Calendar detection reads `options.timerConfig.definitions` (raw, pre-merge) because reading the merged `config.timerConfig` recurses (confirmed: infinite recursion). Checker `check-timer-stagger.py` now fails a calendar timer with OnActiveSec, a monotonic timer without OnActiveSec, and a monotonic timer that still has OnBootSec; an empty OnBootSec list counts as absent.
