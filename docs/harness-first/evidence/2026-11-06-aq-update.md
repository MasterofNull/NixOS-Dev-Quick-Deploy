## Residual Risk
- Not run against real nix, a real origin or the real `aq-land`/`aq-deploy-current`; all are stubs. The first live run is the real test.
- `aq-deploy-current` does its own `git pull --ff-only origin main` and cannot be told which revision to deploy. aq-update re-checks origin/main immediately before calling it and validates the running revision afterwards, but a push in that window is detected after the fact, not prevented. Needs a `--rev <sha>` (or env) option from the sibling slice.
- CI's `nix build` of llama-cpp and the full toplevel is not run locally (hours); only the evaluation commands are. The hosted nix-build job remains the build gate on the lock PR.
- aq-land lives on branch s3-land until S3 merges; until then the CLI test needs AQ_LAND_REAL (SKIP otherwise). Real aq-land also runs tier0 and review lanes; none of that was exercised.
- The baseline script was not run for real (needs root). A cached sudo timestamp may have expired after a long rebuild, in which case a second password prompt appears.
- The no-delta path does not refresh the MCP baseline, per the slice; MCP server sources changed without a Nix delta leave the baseline stale until the next rebuild.
- Throwaway worktrees `.agents/delegation/worktrees/aq-update-<run>` are left for aq-worktree-reap.
