## 2. Guard mechanism: rev4 (authorities YAML + static guard S1) vs brief (contract-validator + tier0 + import rule)

Verified on origin/main (`git show`, `git grep`):

- `crates/contract-validator` (Cargo package `harness-contracts`; workspace `Cargo.toml`): `main.rs` 653 lines, `scope_gate.rs` 183 lines. Subcommands `all`, `writable-state`, `memory-surface`, `scope-gate` (`main.rs:71-74`). Checks the agent-memory-surface registry and required doc phrases, NixOS writable-state policy, and slice owned-path scope. It does NOT validate `contracts/` schemas, event envelopes or imports; it is not a general contract validator despite its name.
- Wiring: `scripts/governance/tier0.d/check-owned-scope.sh` calls it only when `OWNED_PATHS` is set, else exits 0 (lines 14-17), fail-closed if the binary is missing. Packaged by `nix/pkgs/harness-contracts.nix`, in the system closure at `nix/modules/roles/ai-stack.nix:1906`. CI `.github/workflows/rust.yml` runs fmt/clippy/test only when `crates/**` changes. So tier0 invokes it only for sliced work with owned paths.
- `contracts/`: `contracts/events/envelope.py` (pydantic `Envelope`, `extra="forbid"`, `SCHEMA_VERSION = 1`, optional HMAC `sig`) and `contracts/config/{__init__,switchboard_profiles}.py` (`CONFIG_SCHEMA_REGISTRY` keyed by config path; ONE config registered). Imported by `scripts/ai/lib/event_log.py`, `trace.py`, `config_loader.py`, `scripts/governance/aq-evidence-collector.py`. Enforced by `tier0.d/check-config-contracts.sh` (validate + round-trip). The real contract enforcement today is Python/pydantic, not the Rust crate.
- `scripts/governance/check-state-authorities.py` (rev4's S1 base): `git grep -n state-authorities origin/main -- scripts .github config nix` finds no call from `tier0-validation-gate.sh`, `tier0.d/` or `.github/workflows/`; only `test-state-authorities.py` in `config/ci-checks.json:2125,2237`. All 10 ledger rows are SPLIT_BRAIN with deadline 2026-10-09 (expired). Rev4 itself says the checker "does not yet fail on a NEW competing writer".

The two mechanisms check different things: rev4 guards protect STATE WRITES by owner (runtime boundary); the brief's validator protects CALL SHAPES (schema) and IMPORT EDGES (code boundary). Neither is wired for its purpose today.

Recommendation, no second registry:
1. `config/system-state-authorities.yaml` stays the only ownership registry (rev4 D6). Add a `contract:` field per aggregate/guard row naming the versioned file under `contracts/`.
2. `contracts/` is the contract index; the existing `CONFIG_SCHEMA_REGISTRY` is the contract registry in use. Extend it to register existing JSON schemas by path (`agent-dispatch-envelope`, `qa-provider-probe-contract`, `capability-lease`, new `ResolvedRunPlan`, review receipt v3, register schema).
3. S1 stays Python (as rev4 specifies): extend `check-state-authorities.py` and `check-config-contracts.sh`, and WIRE them into tier0.d and the required CI check; wiring is the real S1 deliverable.
4. At S9, if import checking is slow or must be fail-closed in the trust path, add a `contracts` subcommand to `crates/contract-validator` (reusing the existing package and the `check-owned-scope.sh` fail-closed wrapper pattern; "Language by Role" favors Rust for trust gates). It reads the same YAML and checks every `contract:` path exists and is versioned, plus the import rule. Owner decision D-R5-3 (default: Python now, Rust at S9).
5. Import-boundary rule: per-context `allowed_imports` in the YAML; check parses Python `import`/`from` and shell `source`/exec of another context's private module. Baseline current violations as dated exceptions (regression-only, per rev4 non-goal on big-bang).
