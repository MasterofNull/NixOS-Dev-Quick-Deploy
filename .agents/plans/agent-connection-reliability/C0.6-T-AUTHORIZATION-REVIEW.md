## Findings

### Architecture and authority — PASS with preserved boundary

The TUI remains the sole registry/process reader; the projector, backend, API, card, and Phase-0
result remain projections. The design authorizes no reconciliation, cancellation, deadline renewal,
lifecycle mutation, provider work, runtime adoption, or second lifecycle store. The nine-file ceiling
is exact, all pre-state checks are frozen, and the active tier0-isolation lease is explicitly excluded.

### Privacy and security — PASS

The allowed payload is closed to enums and bounded aggregate numbers. Task/work IDs, PIDs, paths,
prompts, messages, output and output-derived hashes, argv, URLs, headers, environment values,
credentials, raw provider errors, task timestamps, and free-form source strings are prohibited at
every projection, log, API, card, and metric-label boundary. The backend contract uses fixed argv,
no shell or request-derived arguments, bounded output, closed validation, single-flight refresh, and
typed fallback. The frontend contract excludes source-derived HTML, attribute, class, tooltip, and
URL sinks.

### Typed no-data and Service Coverage — structurally sound, but one authority path is undefined

Null versus assessed zero is correctly distinguished, blank/`--` values are failures, and the new
route, visible existing card, and fresh Phase-0 check are correctly included in one nine-file slice.
However, the closed response requires `coverage.phase0` and `coverage.web_dashboard` and says they
reflect only external evidence (design lines 88 and 113-115), while the data flow terminates at an
external read-only Phase-0 check and explicitly prohibits API self-attestation (lines 49-64). No
authoritative input, persistence location, or read-only adapter is named that can feed those external
facts back into the exact TUI/API body. As written, implementations must either self-attest, invent a
second authority, or leave the dashboard coverage fields permanently `unavailable`. Define the
existing authoritative evidence source and pure input path, or remove these fields from the
self-reported payload and keep external coverage solely in acceptance evidence.

### SRE aggregation contract — revision required

The schema bounds values but does not define the population/window for `timeout_counts`,
`reconciliation_count`, `output_incomplete_count`, or related terminal counters. It also lacks a
deterministic truth table mapping freshness, ages, expired deadlines, stale owners, incomplete output,
budget mismatches, convergence gaps, and coverage into `health` and `deadline_health`. Consequently,
two conforming implementations could produce different counts and severities from identical registry
evidence, and cumulative historical terminal rows could leave health degraded forever. Freeze the
snapshot membership/window, freshness/age thresholds, counter semantics, and worst-severity mapping,
including every assessment/count combination that must reject.

### Generation observability — revision required

The objective covers generation health and the parent incident includes generation silence, but the
closed contract exposes oldest age only for queue and prefill (design lines 82-87 and 144-150). A
currently stuck generation can remain invisible until it becomes a terminal timeout. Add bounded
`oldest_generation_age_s` plus its closed reason/severity behavior, or explicitly bind an equivalent
active generation-silence measurement to the deadline contract. Tests must cover zero, threshold,
threshold+1, stale, future-skewed, and typed no-data cases.

## Authorization controls

The PREPARED_ONLY state, independent-review requirement, exact-head and predecessor checks,
single implementer, maximum 24-hour activation, first-write consumption, non-replay after drift or
correction, staging/commit exclusions, and later independent acceptance are all adequate. These
controls remain non-authoritative until the design defects above are corrected, the subjects are
rehashed, and the amended authorization receives a new exact-subject review.

No implementation, validation execution, staging, commit, live route, provider, network, runtime,
service, deployment, canary, traffic, or lifecycle authority is granted by this review.

VERDICT: REQUEST_REVISION — define the external coverage evidence input, freeze deterministic aggregation/severity semantics, and add active generation-age observability before activation
