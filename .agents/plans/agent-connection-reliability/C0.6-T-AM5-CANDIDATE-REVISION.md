## 3. Frozen provenance-to-producer mapping

### 3.1 Current v1 mapping

| Requested telemetry producer | Authority-bound outer v1 mapping | AM5 result |
|---|---|---|
| local-agent / local executor | **none** | no trusted local-direct fact may be produced |
| switchboard | **none** | no trusted local-direct fact may be produced |
| trusted-observer | **none** | no trusted local-direct fact may be produced |
| dispatcher admission | `record_version=1` plus `admission_producer=dispatcher` | proves only the closed admission record; it does **not** attest a nested local-direct fact |

`lane=local` identifies routing lane, not producer authority. `record_revision` is CAS ordering, not
producer authentication. Nested `local_direct.trusted`, `local_direct.producer`, a copied
`admission_producer`, an unkeyed digest, or a self-described writer identity has zero trust weight.

### 3.2 Deterministic current behavior

- An exact valid v1 outer record with no local-direct field contributes no lifecycle fact. If all
  records are in this state, the aggregate is the schema-valid typed `not_assessed` /
  `source_not_instrumented` projection with every lifecycle number null.
- Any v1-shaped record carrying `local_direct` or any other extra provenance/telemetry key is outside
  the closed v1 schema. It contributes no counts and deterministically yields the typed rejected-source
  projection: `assessment=not_assessed`, `health=blocked`, `source_freshness=unavailable`,
  `deadline_health=unavailable`, all lifecycle numbers null, and `source_invalid` plus
  `coverage_incomplete` when applicable.
- Missing, extra, malformed, wrong-type, wrong-version, nonpositive revision, illegal status,
  unrecognized producer, ambiguous identity, legacy row, duplicate identity, or nested self-asserted
  provenance follows the same rejected-source rule when it attempts to supply local-direct evidence.
  A legacy row with no telemetry remains merely uninstrumented.
- Mixed snapshots cannot partially improve health: one attempted unbound local-direct fact rejects
  the local-direct source as a whole. No valid surrounding row launders it.
- The TUI adapter may construct projector facts only after a future closed writer contract verifies
  them. Under AM5 it constructs no trusted runtime local-direct facts from current registry rows.

### 3.3 Required later authority amendment

Trusted lifecycle telemetry is gated on a separately authorized amendment to the TaskRegistry writer
and `delegation-task-record` schema. That future version must add an exact closed provenance envelope,
name the sole method allowed to write it, bind producer value to authenticated/descriptor-owned writer
context rather than request content, advance record revision under the stable writer lock, and define
the exact mappings for local-agent, switchboard, and trusted-observer. It must also resolve the
same-account forgery residual threat or explicitly bound its assurance class.

That future writer/schema amendment is outside AM5's nine files. Until it lands and is independently
accepted, the dashboard correctly renders Local Direct Lifecycle as not instrumented/unavailable.

## 4. Frozen ordinary CheckResult descriptions

The immutable QA-evidence consumer accepts exactly four keys — `layer`, `id`, `status`, and
`description` — for these records, with integer `layer=5`, the exact ID, closed PASS/FAIL/SKIP status,
no `details`, no extra key, and these exact UTF-8 literals:

| ID | Exact serialized `description` |
|---|---|
| `0.10.42` | `local-direct lifecycle route contract` |
| `0.10.43` | `local-direct Agent Ops card visibility` |

The descriptions do not vary by status, host availability, error, or reason. Phase-0 must construct
these CheckResults with an empty `reason` so the generic serializer does not append text. Diagnostic
details stay in bounded test output/internal evidence and never alter the immutable record shape.

The existing inclusive evidence-age rule is unchanged: age `0..300` seconds is eligible; age greater
than 300 is unavailable. Missing/extra fields, boolean or wrong layer, wrong ID/description/type,
duplicate ID, unknown status, nonempty details, or description drift maps the affected coverage check
to blocked. Tests use the literals directly and must fail when either side drifts.
