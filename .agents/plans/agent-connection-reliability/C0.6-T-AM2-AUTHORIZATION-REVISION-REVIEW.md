## Prior-blocker adjudication

### Immutable external coverage and anti-self-attestation — PASS

The coverage input is now implementable inside the frozen nine-file ceiling. Phase-0 ID `0.10.42`
represents the canonical route contract and ID `0.10.43` represents deployed card/loader visibility
as two ordinary `CheckResult` records. The design explicitly forbids `details`, description parsing,
embedded sub-results, and generic serializer changes. This matches the existing serializer's closed
`id` and `status` surface and requires only the already-authorized `phase0.py` edit.

The TUI reads only `qa_evidence_store.production_store().read_latest(max_age_seconds=300)`, whose
immutable artifact is selected by the verified hash-bound CAS pointer. Ages from zero through exactly
300 seconds are eligible; older valid evidence or no evidence maps to unavailable. Each ID must occur
exactly once. PASS maps to healthy, FAIL to blocked, SKIP to unavailable, and consumer-side ERROR to
blocked. ERROR is not added to `CheckResult.Status`; it is the closed result of a fresh candidate's
missing/duplicate ID, malformed result/status, or pointer/artifact/schema/producer/integrity failure.
Provenance and free-form fields are discarded before projection.

The route and card checks independently inspect their deployed subjects before the existing aq-qa
publisher persists the invocation. The TUI consumes only the preceding published artifact on its
next refresh and cannot consume the API response, a same-refresh candidate, loose JSON, or an
unpublished run. The one-run/one-refresh lag is therefore unidirectional and does not permit API
self-attestation or a second writer/store.

### Deterministic source rejection and severity — PASS

Malformed, contradictory, unknown, future-invalid, or required-field-incomplete trusted source input
is rejected before aggregation. It produces the closed rejected-source projection:
`assessment=not_assessed`, all lifecycle numerics null, `source_freshness=unavailable`,
`deadline_health=unavailable`, overall `health=blocked`, and only applicable closed rejection reasons
plus coverage incompleteness where needed. It cannot invent integer zeroes or partially aggregate an
invalid population. In contrast, a structurally valid assessed record whose accepted deadline has
expired preserves its trustworthy integer observations and is assessed/blocked. Ordered evaluation
resolves the repeated missing-deadline condition in favor of the earlier rejected-source row.

The active population, five-minute half-open terminal window, integer-millisecond arithmetic,
floor-to-seconds ages, 10/60-second source freshness, five-second future-skew bound, overflow
rejection, empty-population zero, no-data null, deadline remaining-time floor, and worst-severity
composition are frozen. The valid-source severity behavior is deterministic and cannot clamp or
count unbounded history.
