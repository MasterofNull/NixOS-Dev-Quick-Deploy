## Remaining blocking ambiguities

### 1. Authority-bound producer mapping is not frozen

The specification correctly rejects nested `local_direct.trusted` and `local_direct.producer` as
self-attestation. It requires trust to come from the existing strict TaskRegistry authority, but does
not define the exact accepted outer record shape or deterministic mapping to projector producers
`dispatcher`, `switchboard`, and `trusted_observer`.

The existing strict `_m2a_read_records()` boundary proves regular-file, size, framing, and JSON-object
integrity; it accepts arbitrary record keys. The existing sole writer creates
`record_version=1`, positive `record_revision`, and `admission_producer=dispatcher`, but does not own a
`local_direct` field or mappings for switchboard/trusted-observer facts. Therefore a synthetic outer
record can carry those sole-writer-looking fields plus an unauthorized nested `local_direct` object,
and the AM4 documents do not specify which exact check distinguishes it from future writer-owned
evidence. Conversely, strict rejection of every extra field means no current success vector exists.

Freeze one implementable rule before activation. For example: accept only an exact versioned outer
record contract and explicitly map each named, writer-owned provenance field/value to one projector
producer; or declare all current `local_direct` fields untrusted and typed unavailable until a later
writer/schema amendment. Identify the exact TaskRegistry read method and required revision/identity
checks. Do not require a “strict outer-authority success” test until a current contract can actually
produce such a fact.

### 2. Fixed CheckResult descriptions are unnamed

The correction says each expected ID must carry “the fixed canonical description for that ID,” but
does not freeze either literal. An implementer could choose arbitrary descriptions and make its tests
agree, defeating exact artifact-shape interoperability. Bind the exact description string for
`0.10.42` and `0.10.43` in the correction specification and authorization.

These are governance-contract defects, not requests to broaden implementation. Both can be resolved
without changing the nine candidate paths or any live authority, followed by a fresh exact-subject
review.
