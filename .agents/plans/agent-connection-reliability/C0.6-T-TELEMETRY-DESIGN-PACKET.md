## 3. Authority and data flow

```text
existing bounded registry/progress evidence
  -> aq-tui-dashboard source adapter (sole registry/process reader)
  -> agent_ops_projection.py pure closed aggregate
  + verified immutable aq-qa evidence selected by qa_evidence_store's CAS pointer
  -> aq-tui-dashboard --local-direct-health-json (sanitized object only)
  -> dashboard backend bounded subprocess/cache
  -> GET /api/aistack/agent-ops/local-direct-health
  -> existing Agent Ops Status card / Local Direct Lifecycle section
  -> external Phase-0 live visibility check
```

The lifecycle registry and trusted progress evidence remain authoritative for observations. The
projector, TUI, API, card, and Phase-0 result are projections. Monitoring is read-only and may report
a stale owner; only the existing named reconciler or future broker may repair one. The API response
cannot self-attest that its route/card is deployed or visible; live Phase-0 evidence supplies that
external coverage fact.

Coverage has one unidirectional external-evidence path. The TUI may use the existing read-only
`qa_evidence_store.production_store().read_latest(max_age_seconds=300)` verifier to consume the
immutable `aq.qa-evidence.v1` artifact selected by its hash-bound CAS pointer. Coverage is represented
by two ordinary, independently serialized `CheckResult` records: Phase-0 ID `0.10.42` is the local
direct route-contract check and Phase-0 ID `0.10.43` is the deployed card/loader visibility check.
These IDs are frozen and non-conflicting at this base. Neither check uses `details`, parses
`description`, embeds sub-results, or changes the generic serializer. No repository projection, loose
JSON, API response, dashboard value, or model claim is coverage authority.

The route check independently reads and validates the canonical route. The card check independently
reads the deployed card/loader bytes and rejects blank or `--` rendering. The existing aq-qa publisher
writes both ordinary results into the immutable artifact. On the next refresh the TUI projects only
that already-published evidence. It may not use results from the current API refresh, an unpublished
run, or a same-refresh candidate. This deliberate one-run/one-refresh lag prevents the API from
attesting itself. Reading this existing authority requires no new writer, store, environment
override, generic serializer edit, or tenth implementation file.

The QA-evidence age and status mapping are frozen as follows. The verifier receives
`max_age_seconds=300`; an artifact age from zero through exactly 300 seconds is eligible, while age
greater than 300 seconds is stale. Each expected ID is selected exactly once from a verified artifact.

| Verified QA evidence state | Coverage value for that check |
|---|---|
| `PASS` | `healthy` |
| `FAIL` | `blocked` |
| `SKIP` | `unavailable` |
| `ERROR` | `blocked` |

`ERROR` is a closed consumer-side integrity state, not a new `CheckResult.Status` enum. It means a
fresh otherwise-selected artifact has a missing or duplicate expected ID, an unknown/malformed
status, malformed result shape, pointer/artifact mismatch, invalid hash/JSON/schema, unauthorized
producer, invalid completion time, or another verifier integrity failure. No pointer/artifact yet,
or a valid artifact older than 300 seconds, maps both checks to `unavailable`; it is not an integrity
`ERROR`. A publisher/store read failure with an existing but unverifiable candidate is `ERROR` and
therefore `blocked`. `coverage.phase0` mirrors ID `0.10.42`; `coverage.web_dashboard` mirrors ID
`0.10.43`. Neither `SKIP` nor `unavailable` can satisfy completion or canary activation.

## 4. Closed projection contract

`aq.local-direct-health.v1` is a required top-level `local_direct_health` member of the Agent Ops v2
projection. It is also the exact body returned by the sanitized TUI mode and web route. Unknown keys,
unknown enum members, booleans where integers are required, negative counts, values above documented
bounds, non-finite numbers, and inconsistent assessment/count combinations reject.

Required fields:

| Field | Closed values / bound |
|---|---|
| `schema_version` | exactly `aq.local-direct-health.v1` |
| `assessment` | `assessed`, `not_assessed` |
| `health` | `healthy`, `degraded`, `blocked`, `unavailable` |
| `source_freshness` | `fresh`, `stale`, `unavailable` |
| `deadline_health` | `healthy`, `degraded`, `blocked`, `unavailable` |
| `phase_counts` | exact keys `queue`, `prefill`, `generation`, `cleanup`, `terminal`; integer 0..1,000,000 or null |
| `oldest_queue_age_s`, `oldest_prefill_age_s`, `oldest_generation_age_s` | integer 0..31,536,000 or null |
| `active_deadline_count`, `expired_active_count` | integer 0..1,000,000 or null |
| `minimum_remaining_ms` | integer 0..86,400,000 or null; aggregate only, never a deadline timestamp |
| `timeout_counts` | exact keys `queue`, `prefill`, `generation`, `cleanup`; integer 0..1,000,000 or null |
| `generation_silence_exceeded_count`, `stale_owner_count`, `reconciliation_count`, `output_incomplete_count`, `budget_mismatch_count`, `terminal_convergence_gap_count` | integer 0..1,000,000 or null |
| `coverage` | exact keys `projection`, `phase0`, `web_dashboard`; `healthy`, `blocked`, `unavailable` |
| `reason_codes` | unique bounded members from the vocabulary below, maximum 16 |

Allowed phases are only `queue`, `prefill`, `generation`, `cleanup`, and `terminal`. Legacy
`queued`, `starting`, and compatible trusted progress values are normalized deterministically;
unknown values block the aggregate with `phase_invalid` and are never forwarded.

Allowed reason codes are:

`source_not_instrumented`, `source_stale`, `source_invalid`, `phase_invalid`,
`deadline_missing`, `deadline_expired_active`, `queue_age_exceeded`, `prefill_age_exceeded`,
`generation_silence_exceeded`,
`timeout_observed`, `stale_owner_observed`, `output_incomplete_observed`,
`budget_mismatch_observed`, `terminal_convergence_gap`, `coverage_incomplete`, and `healthy`.

The aggregate may consume only trusted evidence produced by the dispatcher, switchboard, or trusted
observer and carrying the C0/C0.6 closed reason/evidence vocabulary. Prompt/model assertions and
untrusted progress cannot populate counts or improve health.

### Frozen population, window, freshness, and arithmetic

The pure projector receives an injected reference clock and one bounded trusted snapshot. Neither
clock nor task timestamps cross the output boundary. Arithmetic is integer milliseconds internally
and floors nonnegative displayed ages to seconds.

- **Active population:** unique, nonterminal records whose authoritative lifecycle state is queue,
  prefill, generation, or cleanup at snapshot time. Duplicate task/run identities, contradictory
  states, missing accepted deadlines, or future phase transitions fail the aggregate closed.
- **Terminal population:** unique trusted terminal transitions in the half-open interval
  `(reference_time - 300 seconds, reference_time]`. `phase_counts.terminal`, timeout counts,
  reconciliation, incomplete-output, budget-mismatch, and terminal-convergence-gap counters use only
  this five-minute population. Older history is excluded rather than degrading health forever.
- **Phase ages:** oldest queue, prefill, and generation age are maxima over their active population
  from the trusted phase-entry time. Empty assessed populations yield numeric zero. Missing or
  future-skewed phase-entry evidence rejects; no-data sources yield null.
- **Generation silence:** each active generation record carries the trusted last-byte/progress time
  and its accepted generation-silence cap. `generation_silence_exceeded_count` counts active records
  whose silence age exceeds that cap; the oldest generation age remains visible even before the cap.
  Progress or model assertions cannot renew this time.
- **Deadline arithmetic:** active deadline count and minimum remaining time use the immutable accepted
  lifecycle deadlines. Remaining time floors at zero; an expired active record increments
  `expired_active_count` and blocks deadline health.
- **Source freshness:** a verified adapter read completed no more than 10 seconds before the injected
  reference time is `fresh`; a last accepted read older than 10 and no older than 60 seconds is
  `stale`; older, absent, hash-invalid, malformed, or unavailable input is `unavailable`. Future skew
  above five seconds rejects. The backend's two-second cache never extends these limits.

All counters saturate by rejection, not clamping: a computed value above its schema maximum rejects
the candidate. Stable task/run identity is used only for deduplication and never emitted.

### Deterministic assessment and severity truth table

Evaluation is ordered; the first matching highest-severity row wins. `deadline_health` is computed
independently and overall `health` is the worse of source, deadline, lifecycle, and coverage health.

| Condition | `assessment` | `deadline_health` | overall contribution | Required reason |
|---|---|---|---|---|
| Track-A fields absent | `not_assessed` | `unavailable` | `unavailable` | `source_not_instrumented` |
| Source absent/older than 60s | `not_assessed` | `unavailable` | `unavailable` | `source_invalid` or `source_not_instrumented` |
| Malformed/contradictory/unknown trusted facts or a missing required active deadline | `not_assessed` | `unavailable` | `blocked` | `source_invalid`, `phase_invalid`, or `deadline_missing` |
| Any expired active deadline, missing active deadline, budget mismatch, stale owner, or terminal convergence gap | `assessed` | `blocked` for deadline/mismatch; otherwise no improvement | `blocked` | matching closed reason |
| Source stale, any phase-age/silence cap exceeded, recent timeout, incomplete output, or reconciliation | `assessed` | `degraded` for age/silence/timeout; otherwise no improvement | `degraded` | matching closed reason |
| Any external coverage `blocked` | unchanged | unchanged | `blocked` | `coverage_incomplete` |
| External coverage `unavailable`, with no worse condition | unchanged | unchanged | `degraded` | `coverage_incomplete` |
| Fresh valid source, all assessed anomaly counters zero, active deadlines valid, and all coverage healthy | `assessed` | `healthy` | `healthy` | `healthy` only |

`healthy` is mutually exclusive with every other reason. `not_assessed` requires every lifecycle
count/age/remaining value to be null. `assessed` requires every count to be an integer and each empty
population age to be zero. Any other assessment/value or reason/severity combination rejects.

Malformed, contradictory, unknown, or required-field-incomplete source input is rejected as a whole
before aggregation. The projector emits the typed rejected-source row above: all lifecycle numeric
fields are null, `source_freshness=unavailable`, `deadline_health=unavailable`, overall
`health=blocked`, and only the applicable closed rejection reason plus `coverage_incomplete` when
needed. It never invents integer counts, partially aggregates the malformed candidate, or relabels it
as assessed. This differs from a structurally valid assessed record whose accepted deadline has
expired: that record retains its trustworthy integer observations and uses the assessed blocked row.

### Typed no-data semantics

Missing Track-A fields are expected before runtime adoption. They produce a valid response with:

- `assessment=not_assessed`, `health=unavailable`, `source_freshness=unavailable`, and
  `deadline_health=unavailable`;
- every count/age/remaining-time value, including generation age and silence count, set to null,
  never zero;
- `coverage.projection=healthy` after the pure contract is installed, while Phase-0 and web coverage
  reflect only external evidence; and
- exactly `source_not_instrumented` plus any external `coverage_incomplete` reason.

Zero means an assessed source observed zero. Null means no trustworthy measurement. The dashboard
renders fixed text such as `Not instrumented` or `Unavailable`; it must never render `--`, blank
content, `0`, or `healthy` for no-data.

## 5. Privacy, security, and cardinality

The projection and every downstream surface forbid task/work IDs, PIDs, process identities,
timestamps tied to individual tasks, paths, prompts, messages, model output, output hashes,
artifacts, argv, URLs, headers, raw provider errors, credentials, environment values, and free-form
strings. Fixed schema/version/enums and bounded aggregate numbers are the only payload.

The TUI's additional QA input is the existing verified immutable QA-evidence reader described in
section 3. It consumes only closed verdict/status fields; run IDs, artifact names, hashes, paths, and
timestamps are discarded before projection. The backend invokes the TUI by an argv vector using the dashboard interpreter and a fixed mode; no
shell, request-derived argument, query, body, task identifier, registry path, or environment override
is accepted. It uses one in-flight refresh and a monotonic two-second accepted-value cache. Timeout,
malformed JSON, schema failure, oversized output, nonzero exit, or private canary blocks the candidate
and returns the last accepted value as stale; without one it returns typed unavailable. Errors exposed
to the API/card are fixed codes only.

Metrics labels, if later exported, are limited to the closed phase, C0 reason, lane=`local`, and
health/status enums. All numeric task-specific values remain measurements, never labels.

## 6. Dashboard and Phase-0 behavior

The existing **Agent Ops Status** card gains a visually distinct **Local Direct Lifecycle** section.
Its badge is the worst severity of coordinator drift/profile health and local-direct health; a
nominal coordinator must not hide unavailable or blocked local lifecycle evidence. The section shows:

- health and deadline-health state;
- queue, prefill, generation, cleanup, and terminal counts;
- oldest queue, prefill, and generation age, plus active generation-silence violations;
- aggregate minimum remaining deadline duration;
- timeout counts by phase;
- stale owners and reconciliation count;
- incomplete output, budget mismatch, and terminal-convergence gaps; and
- Phase-0/web coverage state.

All labels come from fixed frontend maps and all values are numbers or fixed no-data text. No source
string is assigned to `innerHTML`, HTML attributes, tooltip text, CSS class names, or URLs.

Phase-0 ID `0.10.42` runs the focused pure and canonical-route contract tests. Phase-0 ID `0.10.43`
confirms the existing deployed card and loader bytes and rejects blank/`--` no-data rendering. When
the dashboard is live, `0.10.42` performs its read-only GET to the canonical route and validates the
closed response. Host unavailability is an honest `SKIP` for the affected check during repo-only
validation, maps to `unavailable`, and cannot satisfy C0.6 completion or canary activation.

## 9. Activation and rollback gates

C0.6-T may land dormant with typed no-data; that does not complete C0.6. Track A may be prepared only
after C0.6-T exact-hash acceptance. A later harmless canary may activate only when:

- all admitted canary tasks appear in queue/prefill/generation within one dashboard refresh;
- 100% terminate inside their declared lifecycle deadline including cleanup reserve;
- stale-owner, budget-mismatch, and terminal-convergence-gap counts are zero after convergence;
- expected timeout/incomplete probes appear under their exact phase/reason without false success; and
- Phase-0, live dashboard coverage, and the parent parity/reliability suites pass.

Any missing/blank field, privacy canary, unknown enum, source/schema error, stale owner after the
accepted convergence window, nonzero budget mismatch or convergence gap, late completion, or
dashboard/API disagreement blocks activation. Rollback disables new canary admission through the
reviewed runtime control; it never deletes evidence, weakens typed no-data, mutates monitoring state,
or restores an undeclared timeout/token override.
