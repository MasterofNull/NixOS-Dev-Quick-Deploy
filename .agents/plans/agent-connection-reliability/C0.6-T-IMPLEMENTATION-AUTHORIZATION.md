   Agent Ops projection and both Draft-2020-12 schemas;

3. add one dashboard-local, read-only, no-argument GET route with a bounded argv subprocess,
   monotonic accepted-value cache, closed validation, typed unavailable fallback, and fixed errors;
4. extend the existing Agent Ops card with the separately labeled Local Direct Lifecycle section and
   worst-severity badge behavior without adding another timer or source-string HTML sink;
5. add focused pure/API/frontend privacy and adversarial tests; and
6. register ordinary Phase-0 ID `0.10.42` for the focused route contract and ordinary Phase-0 ID
   `0.10.43` for deployed card/loader visibility, using the existing generic `CheckResult` serializer
   without `details`, description parsing, embedded sub-results, or serializer changes.

The implementation must preserve typed no-data: unavailable/not-instrumented fields are null and
fixed text, while assessed zero remains numeric zero. It must expose queue/prefill/generation/cleanup/
terminal counts, oldest queue/prefill/generation age, active generation-silence violations, deadline
health, bounded remaining-time health, timeout counts, stale owners/reconciliation, incomplete
output, budget mismatch, convergence gaps, and external coverage without task-level material.

Aggregation is frozen to the design's active population plus a five-minute half-open terminal
window. Source reads are fresh through 10 seconds, stale through 60 seconds, and unavailable after
that; future skew over five seconds rejects. Queue/prefill/generation ages use trusted phase-entry
evidence, generation silence uses trusted last-byte/progress evidence and the accepted per-task cap,
and deadline arithmetic uses immutable accepted lifecycle deadlines. Implementations must apply the
design's ordered severity truth table exactly; they may not invent thresholds, clamp overflow, count
unbounded history, or treat missing data as zero.

Malformed, contradictory, unknown, or required-field-incomplete trusted source input is rejected
before aggregation. It must emit `assessment=not_assessed`, null lifecycle numeric fields,
`source_freshness=unavailable`, `deadline_health=unavailable`, overall `health=blocked`, and the
applicable closed rejection reason. It must not synthesize integer counts or partially aggregate an
invalid candidate. A structurally valid assessed record with an expired accepted deadline remains an
assessed blocked observation.

## 4. Privacy, authority, and monitoring invariants

- Only trusted dispatcher/switchboard/observer facts may improve health or populate counts.
- Phase/reason vocabularies are closed; unknown or contradictory facts block rather than pass through.
- No task/work ID, PID, path, prompt, message, output, output-derived hash, artifact, argv, URL,
  header, environment value, credential, raw provider error, task timestamp, or free-form source text
  may cross the sanitized projection, TUI, API, logs, card, or metric-label boundary.
- Monitoring remains read-only and cannot reconcile, cancel, extend a deadline, renew a lease, alter
  lifecycle state, or claim runtime authority.
- The API payload cannot self-attest web coverage. Only live Phase-0 and independent acceptance may
  establish route/card coverage.
- External coverage enters only through the existing `qa_evidence_store` verified immutable artifact
  selected by its hash-bound CAS pointer through
  `production_store().read_latest(max_age_seconds=300)`. ID `0.10.42` maps only to `coverage.phase0`;
  ID `0.10.43` maps only to `coverage.web_dashboard`. Artifact ages zero through exactly 300 seconds
  are eligible; ages above 300 seconds are stale. `PASS` maps to `healthy`, `FAIL` to `blocked`,
  `SKIP` to `unavailable`, and consumer-side `ERROR` to `blocked`. `ERROR` means a fresh candidate
  has a missing/duplicate expected ID, malformed/unknown status or result, pointer/hash/JSON/schema/
  producer/completion-time verification failure, or another existing-candidate integrity failure.
  No artifact yet and a valid stale artifact map to `unavailable`. Provenance identifiers, paths,
  hashes, timestamps, and all free-form details are discarded before projection.
- The TUI consumes only the preceding published immutable artifact on its next refresh. It may not
  use the current API response, current-refresh candidate, loose JSON, or unpublished run; this
  preserves the one-run/one-refresh anti-self-attestation lag.
- The existing Agent Ops drift/profile fields keep their meaning. Local-direct unavailability or a
  blocked state must not be hidden behind a nominal coordinator badge.
- Blank and `--` values are failures. Fixed `Not instrumented`/`Unavailable` text is required before
  Track A supplies runtime evidence.
