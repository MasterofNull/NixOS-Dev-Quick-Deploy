## Blocking findings

### Backend fallback violates schema and freshness

`aistack.py:3098-3107` validates a cached object and then mutates `source_freshness` to `stale`
without validating the result. A valid `assessment=not_assessed` payload becomes a schema-invalid
not-assessed/stale/null payload. The focused test at
`test-agent-ops-local-direct-health-web.py:141-152` creates this exact case and asserts the invalid
stale value instead of validating the returned object.

The failure path also ignores the cache success timestamp. Repeated adapter failure can return old
assessed lifecycle integers indefinitely, extending evidence past the frozen 60-second unavailable
boundary. Preserve unavailable semantics for no-data, allow assessed stale fallback only within the
remaining accepted-age window, return typed unavailable after 60 seconds, and validate the final
fallback before return.

### Embedded schema and backend validator are weaker than the standalone schema

The standalone schema correctly requires every lifecycle numeric to be an integer for assessed
payloads and requires healthy coverage for healthy health. The embedded Agent Ops schema at
`agent-ops-projection.schema.json:201-216` does neither: assessed numerics remain nullable and the
healthy rule omits coverage. The backend has the same drift. `aistack.py:3045-3066` accepts assessed
objects with mixed integer/null values, while `aistack.py:3071-3074` allows healthy objects without
enforcing fresh source, healthy deadline, or healthy coverage. Align both validators exactly with the
standalone contract and add adversarial parity vectors for inconsistent states.

### Subprocess output is not hard bounded

`aistack.py:3080-3088` passes a stream-reader limit but calls `proc.communicate()`, which accumulates
stdout before the post-read length check. That limit is not a total-output cap for communicate. Use a
true max-plus-one bounded read, terminate/reap on overflow, and test max, max+1, continuous output,
timeout, and cleanup.

### QA CheckResult shape is not exact

The TUI correctly uses CAS-verified immutable evidence, the inclusive 300-second window, ordinary
IDs `0.10.42`/`0.10.43`, exact status mapping, and next-refresh anti-self-attestation. However,
`aq-tui-dashboard:131-137` rejects only extra keys. A result missing `layer` or `description` passes
when ID and status exist, although malformed result shape must map to ERROR/blocked. Require the exact
ordinary CheckResult key set and closed types, with missing-key, wrong-type/layer, duplicate,
extra-key, and unknown-status tests.

### Phase-0 skips offline tests in safe mode

`phase0.py:2227-2235` returns SKIP before invoking either focused suite when `dashboard_safe` is true.
The design requires `0.10.42` to exercise focused pure/web tests offline and skip only its host GET
when unavailable. Run offline suites before the host-only branch and add a safe-path execution test.

### Deadline and adversarial boundaries are incomplete

The projector implements the half-open terminal window, 10/60-second freshness, five-second future
skew, generation age/silence, typed no-data, and high-level severity for covered cases. But an active
deadline exactly equal to the reference time is unexpired at `agent_ops_projection.py:695-696`; the
lifecycle contract ends at that deadline. The five new projection tests also omit required complete
phase/reason mapping, 0/max/max+1, non-finite, cleanup, terminal-counter, severity, and recursive
privacy matrices. Correct the equality boundary and add the required adversarial vectors.
