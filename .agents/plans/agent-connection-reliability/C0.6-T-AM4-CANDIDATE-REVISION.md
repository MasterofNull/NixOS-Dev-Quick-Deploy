## 3. Required corrections

### 3.1 Cache fallback and freshness

- The cache records accepted payload plus monotonic acceptance time. Fallback operates on a deep copy;
  it never mutates the accepted cache entry.
- Every returned payload, including fallback and typed unavailable, passes the complete shared
  semantic validator immediately before return.
- A `not_assessed` cached value remains the schema-valid typed unavailable projection. It is never
  relabeled `stale` while retaining null fields.
- An `assessed` cached value may be returned as stale only while its effective source age is greater
  than 10 and no greater than 60 seconds. The effective age includes both the source age already
  represented when accepted and monotonic time elapsed in the backend cache.
- After 60 seconds, or when source age cannot be bounded, the backend returns the schema-valid typed
  unavailable payload with every lifecycle number null. No old count, age, deadline, or reason is
  retained. Exact boundaries 10, 10+epsilon, 60, and 60+epsilon are tested.
- Timeout, nonzero exit, malformed JSON, invalid UTF-8, schema error, oversize, cancellation, and
  child-cleanup failure all use this same fail-closed rule.

### 3.2 Validator semantic parity

The standalone Draft-2020-12 local-health schema is the normative payload contract. The embedded
Agent Ops schema and all dependency-free runtime validators must accept and reject the same golden
vectors. In particular:

- `assessed` requires every lifecycle numeric to be an integer, including empty-population zero;
- `not_assessed` requires every lifecycle numeric to be null and unavailable freshness/deadline state;
- healthy requires fresh source, healthy deadline, all three coverage members healthy, zero anomaly
  counters, and exactly `reason_codes=["healthy"]`;
- unavailable, degraded, and blocked combinations follow the design truth table exactly;
- unknown keys/enums, booleans-as-integers, negative/overflow/non-finite values, duplicate reasons,
  contradictory coverage/reasons, and mixed null/integer assessed payloads reject; and
- embedded schema, standalone schema, pure projector, TUI output validator, backend validator, and
  final API response run the same accepted/rejected vector corpus. A weaker compatibility validator
  or post-validation mutation is prohibited.

### 3.3 Bounded child execution and single-flight cleanup

- The dashboard child reader enforces a combined stdout-plus-stderr cap of 65,536 bytes before
  unbounded accumulation. It reads both pipes incrementally with at most cap-plus-one aggregate bytes;
  the asyncio stream `limit` and a post-`communicate()` length check are not sufficient.
- Exact max bytes may proceed to UTF-8/JSON/schema validation; max+1 or continuous output terminates
  and reaps the child and enters fail-closed cache behavior. Stderr is bounded even though it is never
  exposed.
- One monotonic two-second child deadline covers spawn, reads, exit, and bounded cleanup. On timeout,
  overflow, route cancellation, refresh cancellation, parse failure, or nonzero exit, close/cancel
  readers, terminate the owned child, wait a bounded grace, kill if needed, and always reap it.
- The shared refresh task owns the child. Cancellation of one route waiter must not abandon or
  multiply the shared refresh; shared-refresh cancellation must execute the same child cleanup.
  Tests assert no live child/read task remains and a later request can start exactly one refresh.
- No shell, request-derived argument, environment override, prompt, task ID, path, raw stderr, or free
  error text crosses the route or log boundary.

### 3.4 Exact QA evidence and authority-bound trust

For IDs `0.10.42` and `0.10.43`, the immutable artifact consumer accepts exactly the ordinary
serialized `CheckResult` object:

```text
keys = {layer, id, status, description}
layer = 5
id = the selected expected ID
status = PASS | FAIL | SKIP
description = the fixed canonical description for that ID
```

`details` and every extra key are forbidden for these checks. Missing keys, wrong types, booleans for
layer, wrong layer/ID/description, unknown status, duplicates, malformed artifact, or wrong producer
map that check to blocked. A verified artifact age from zero through exactly 300 seconds is eligible;
greater than 300 seconds is unavailable. The exact two IDs remain globally unique in both Phase-0
registries.

Registry `local_direct.trusted=true` or `local_direct.producer=*` is not proof. The adapter may improve
health only when the outer record was read through the existing strict `TaskRegistry` authority and
its producer/revision provenance is bound to that sole-writer contract. It derives the projector's
trusted producer enum from verified outer authority; it never copies a nested self-asserted trust bit
or producer string. If the existing record lacks enough authority-bound provenance for dispatcher,
switchboard, or trusted-observer attribution, the fact is rejected and the aggregate remains typed
unavailable/blocked until a separately reviewed Track-A writer contract supplies it. AM4 does not
edit a registry writer, invent an attestation, or weaken this rule to make fixtures pass.

Tests must include forged nested trusted/producer claims, strict outer-authority success, legacy and
ambiguous outer records, revision/provenance mismatch, unauthorized producer, and mixed trusted/
untrusted snapshots. No task/run identity or provenance material may leave the projector.

- A successful live GET is validated against the full closed semantic schema, not only
  `schema_version`. Malformed, contradictory, private, extra-key, or no-data-as-zero responses fail.
- Check `0.10.43` remains host-only, verifies fixed card/loader bytes, and never turns a repository

- No new poller/timer, `innerHTML` source sink, blank value, or `--` typed no-data is introduced.

### 3.6 Projector ordering and complete adversarial matrix

- An active deadline equal to the injected reference time is expired; use `deadline <= now`, not
  `deadline < now`.
- `timeout_observed` is emitted only when at least one in-window terminal record carries a valid
  timeout phase. Reconciliation alone never fabricates timeout evidence.
- Validate `terminal_at_ms` before window membership; accept the design interval
  `(now-300000, now]`, reject future skew above five seconds, deduplicate by authority-bound identity,
  and make aggregation independent of input ordering. Conflicting duplicate terminal records reject.
- Add exact equality, below/above window, phase mapping, cleanup, generation-silence, deadline,
  source-freshness, cache max/max+1, continuous oversize, timeout/cancellation/reap, semantic-schema
  parity, recursive privacy, CheckResult shape/freshness, and Phase-0 ID uniqueness tests.
- Cover integer 0, each field maximum, maximum+1, boolean, negative, and non-finite inputs; every
  phase/reason and severity row; empty/no-data; malformed/unknown/untrusted/future-skewed facts; all
  terminal counters; stable reason ordering; and prompt/task/path/PID/argv/URL/header/credential/raw
  provider error/output/provenance canaries across projector, TUI, API, logs, and rendered card.
