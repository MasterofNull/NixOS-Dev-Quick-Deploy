## 3. Required corrections

### 3.1 Frontend coordinator availability and worst-severity composition

The frontend must not use object truthiness as coordinator availability.
Coordinator data is available only when it is an object and its explicit
`available` member is not `false`. A missing response, `null`, malformed
response, or `{ "available": false, ... }` is coordinator-unavailable.

Local-direct retrieval and rendering remain independent. Coordinator failure
must not suppress, clear, or prevent local-direct rendering. The combined
Agent Ops badge must deterministically select the worst severity across the
coordinator and local-direct states using the already-frozen severity order.

Regression tests must exercise the exact backend fallback object with
`available: false` combined with every local-direct state, plus available,
missing, null, and malformed coordinator responses. They must prove local data
still renders and the badge never improves either source's severity.

### 3.2 Effective cache age on every return path

Every cached return, including the ordinary in-TTL fast path, refresh success,
refresh failure fallback, shared-waiter return, and cancellation fallback, must
pass through one pure effective-age projection and final semantic validation.
No path may return stored payload bytes unchanged.

The cache must retain the accepted payload, its accepted `source_age_s`, and an
injected monotonic acceptance time. At return time:

`effective_source_age_s = accepted_source_age_s + max(0, now_monotonic - accepted_monotonic)`

The projection operates on a copy and may only preserve or worsen health:

- age `<= 10s`: preserve the accepted classification;
- age `> 10s` and `<= 60s`: at least stale/degraded with `source_stale`;
- age `> 60s`: typed unavailable, with assessed values erased to `null`.

It must never extend freshness, remove a worse pre-existing reason, increase
coverage, or mutate the stored accepted payload. Final schema and semantic
validation is mandatory after relabeling.

Regression tests must directly exercise the route's normal fast path and
failure fallback at exactly 10 seconds, immediately above 10, exactly 60, and
immediately above 60, with a deterministic injected clock.

### 3.3 Closed outer `aq.delegation-task-record.v1` validation

Before interpreting registry evidence, the adapter must validate each supplied
record against the exact closed outer `aq.delegation-task-record.v1` key, type,
enum, and value contract. The only permitted top-level keys are:

`record_version`, `task_id`, `lane`, `role`, `access`, `task_class`,
`artifact_expectation`, `created_epoch`, `record_revision`,
`admission_producer`, and `status`.

Their exact value contracts are frozen from the `new_record` branch of
`aq.delegation-task-record.v1`:

| Key | Exact type/value contract |
|---|---|
| `record_version` | integer, exactly `1`; booleans forbidden |
| `task_id` | string matching `^[a-zA-Z0-9][a-zA-Z0-9._:-]{0,127}$` |
| `lane` | one of `local`, `claude`, `codex`, `antigravity` |
| `role` | one of `implementer`, `reviewer`, `researcher`, `orchestrator`, `validator` |
| `access` | one of `writer`, `read_only` |
| `task_class` | one of `code_generation`, `code_review`, `research`, `planning`, `validation`, `analysis`, `documentation`, `testing`, `refactoring`, `debugging` |
| `artifact_expectation` | one of `file_output`, `json_output`, `markdown_output`, `none` |
| `created_epoch` | integer `>= 0`; booleans forbidden |
| `record_revision` | integer, exactly `1`; booleans forbidden |
| `admission_producer` | string, exactly `dispatcher` |
| `status` | string, exactly `queued` |

The adapter validates only this exact outer `new_record` branch. Process-attachment and
transition-request objects are operations rather than registry records and must reject if supplied
as source rows.

Any extra top-level key, nested object where the contract expects a scalar, or
malformed required value rejects the entire source as blocked/source-invalid.
This includes—but is not limited to—attempted `local_direct`,
`local_direct_attempted`, `trusted`, `producer`, `provenance`, or similarly
named fields. Enforcement must derive from exact closed-schema validation, not
from a selective forbidden-name list.

A valid exact v1 record contains no local-direct telemetry and therefore maps
to typed `not_assessed` / `source_not_instrumented`; it must not be promoted to
trusted or assessed evidence. A mixed source containing one invalid record is
rejected as a whole; valid rows may not be selectively salvaged.

Regression tests must cover every permitted field's malformed type/value,
arbitrary unknown keys, the named attempted trust/provenance keys, nested
payload attempts, mixed valid/invalid inputs, and an exact valid v1 record.

### 3.4 One bounded child lifecycle budget

The backend probe gets one absolute monotonic deadline of at most two seconds.
That single budget includes spawn, stdout/stderr read, output-cap enforcement,
terminate, kill, and confirmed reap. Cleanup must not start a new timeout
window. Every await and blocking boundary must consume only the remaining
budget.

Cancellation and shared waiters must not orphan a child, create duplicate
children, or suppress cleanup failures. A normal response or cached fallback
may not be returned until the owned child is confirmed terminal and reaped. If
reap cannot be confirmed within the absolute deadline, the route must raise a
fixed cleanup-integrity failure; it must not suppress that failure or claim a
successful bounded probe.

The implementation must reserve enough budget to escalate from terminate to
kill and reap, enforce the output cap within the same deadline, and retain one
refresh owner under concurrent callers.

Regression tests must place the deadline immediately before, at, and after
spawn, read, output-cap, terminate, kill, and reap boundaries. They must cover
caller cancellation, shared waiters, non-returning terminate/kill/wait test
doubles, total elapsed time, terminal child state, and explicit propagation of
unconfirmed-reap failure.

### 3.5 Terminal timestamp ordering

Any terminal record with `terminal_at_ms < phase_entered_at_ms` is invalid,
regardless of whether the relevant helper currently appears dormant or
unreachable. The candidate must either:

1. enforce the ordering in the reachable validation path and add a direct
   regression test; or
2. remove the unreachable helper and its dead logic, with a regression test on
   the surviving validator.

The existing upper future-skew bound remains unchanged. Ordering failure must
reject the entire source as blocked/source-invalid; it may not degrade to
untrusted partial evidence.
