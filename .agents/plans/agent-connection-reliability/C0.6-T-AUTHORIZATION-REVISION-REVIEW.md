## Prior-blocker adjudication

### Deterministic populations, arithmetic, freshness, and severity — substantively closed, with one invalid-input ambiguity

The revision now freezes a unique active population, a five-minute half-open terminal population,
integer-millisecond arithmetic, floor-to-seconds display, 10/60-second source freshness, five-second
future-skew rejection, null-versus-zero behavior, overflow rejection, deadline arithmetic, generation
silence arithmetic, and worst-severity ordering. These additions resolve the prior cumulative-history
and implementation-divergence defects for valid evidence.

The malformed/contradictory row is still internally inconsistent: section 4 says contradictory facts
and inconsistent assessment/count combinations reject, while the truth table requires malformed or
contradictory facts to produce `assessment=assessed` and `health=blocked`; `assessed` in turn requires
every count to be an integer. The contract does not say which trustworthy integers can be emitted
from an invalid population. The implementation must not synthesize zero counts from malformed input.
Freeze one behavior: reject the candidate into a typed unavailable fallback, or define a separate
closed invalid-source payload whose values cannot be mistaken for observations.

### Active generation age, silence, typed no-data, privacy, and tests — closed

`oldest_generation_age_s` and `generation_silence_exceeded_count` are now bounded first-class fields.
The design binds generation age to trusted phase entry, silence to trusted last-byte/progress time and
the accepted cap, forbids untrusted renewal, and requires zero/threshold/threshold+1, stale,
future-skew, and typed no-data tests. Null means no trustworthy measurement and assessed zero remains
numeric zero. The recursive privacy prohibition covers projection, TUI, API, logs, card, and metrics;
fixed frontend maps and no source-derived HTML/attribute/class/URL sinks are required. This closes the
prior generation-observability blocker.

### External immutable QA coverage — authority is named, but the bound representation is not implementable

The revision correctly names the existing `qa_evidence_store.production_store().read_latest()`
verified immutable artifact and hash-bound CAS pointer as the sole external coverage authority. It
also establishes the correct unidirectional sequence: Phase-0 independently verifies route and
deployed card/loader bytes, the existing publisher persists evidence, and the TUI consumes only the
next refresh, preventing API self-attestation. No second writer or lifecycle authority is introduced.

However, the required evidence shape cannot be produced by the current QA publisher within the exact
nine-file ceiling. `CheckResult.to_dict()` emits only `layer`, `id`, `status`, `description`, and the
existing provider-probe-specific `details`; it has no generic closed sub-result field. C0.6-T requires
one fresh check ID with closed `route_contract` and `card_visibility` sub-results, while the only
authorized QA implementation file is `phase0.py`. Therefore a conforming implementer would have to
do one of the following, all contrary to the frozen grant: parse free-form `description`, overload
provider-specific `details`, modify `scripts/testing/harness_qa/core/result.py` as a tenth file, or
replace the required one-check/sub-result structure with multiple check IDs.

The mapping is also not fully deterministic: missing, stale, malformed, wrong-producer, skipped, or
incomplete evidence is allowed to map to either `unavailable` or `blocked`, and no exact QA-evidence
freshness duration is frozen. Define a representation already supported by the immutable artifact
(for example, two separately frozen check IDs and exact PASS/FAIL/SKIP-to-coverage mappings), or add
the result-contract file to a newly reviewed ceiling and define a generic closed sub-result schema.
Freeze the evidence max-age and exact status mapping at the same time.
