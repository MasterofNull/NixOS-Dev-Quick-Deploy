## 1. Objective and observed defect

C0.3 has independent implementation acceptance, but the Git evidence and authorization lifecycle are
not durably reconciled:

1. current `main` descends from the parentless commit `a0bd5520...`;
2. neither accepted integration commit `c9fe3974...` nor reviewed subject HEAD `d918a21a...` is an
   ancestor of current `main`;
3. both commits still exist as valid local Git objects, but `git fsck --no-reflogs --unreachable`
   reports both as unreachable;
4. no current durable ref names either commit, so ordinary garbage collection may delete the accepted
   objects and the locally reachable history segment even though corresponding document bytes remain
   in the new root;
5. `C0.3-CURRENT-SUBJECT-ACCEPTANCE.md` records `PASS` while intentionally leaving the parent
   authorization `UNCONSUMED`; and
6. the accepted integration already occurred, so leaving the single-use implementation grant
   indefinitely reusable is lifecycle debt and no longer represents operational truth.

This slice preserves the disconnected objects without rewriting `main`, proves what is and is not
connected, and changes the authorization lifecycle from `UNCONSUMED` to `CONSUMED` through a new
additive record. It does not reinterpret implementation acceptance as C0.3 ratification, Cycle-0 exit,
authority-row convergence, or later-slice authorization.

## 3. Target design

### 3.1 Durable evidence refs

Create exactly two annotated evidence tags:

| Ref | Exact target | Meaning |
|---|---|---|
| `refs/tags/aqos-evidence/c0.3/integration-c9fe3974` | `c9fe3974753395ed343fed9e922c9c2ea695129b^{commit}` | preserves the accepted integration lineage |
| `refs/tags/aqos-evidence/c0.3/reviewed-head-d918a21a` | `d918a21a24081d1329efb0e85d4b3695627b4617^{commit}` | preserves the exact HEAD independently reviewed |

Annotated tags are selected instead of reflogs, dangling-object assumptions, or a custom notes ref:

- tag refs keep each exact target and its currently available local history segment
  reachable from garbage collection;
- ordinary Git tag transport can replicate them without rewriting `main`;
- each tag can carry a bounded explanation, the exact target, tree, parent, acceptance candidate
  SHA-256, authorization ID, and the statement `evidence only; grants no authority`; and
- two refs preserve the distinction between integration identity and reviewed composition.

This repository is shallow. Neither tag can prove or preserve history beyond
`a0f79cf...`; “complete ancestry” is expressly not claimed. Fetching or preserving
the hidden parent chain beginning at `d247f7f...` is a separate networked provenance
slice. The local reconciliation remains useful because it protects the exact
accepted/reviewed objects and every currently available ancestor.

The implementation must create both deterministic tag objects first, validate their
parsed contents and peeled targets, then install both previously absent refs in one
atomic `git update-ref --stdin` transaction with zero-old-value CAS checks. It must not force, overwrite,
delete, retarget, or reuse an existing ref. A pre-existing exact ref is treated only as an idempotent
recovery case after its tag object, message, and peeled target all match the authorized contract;
anything else is a hard conflict.

Creating local tags is not proof of remote durability. A later, separately authorized external
publication step may push these exact refs with explicit source:destination refspecs and verify the
remote peeled targets. This design does not authorize network access or a push.

### 3.2 Authorization-consumption truth

Create one additive tracked record:

`.agents/plans/aqos-refoundation-cycle0/C0.3-AUTHORIZATION-CONSUMPTION.md`

Its closed record must contain:

- `authorization_id: auth-c0.3-20260711`;
- the full idempotency key;
- `prior_state: UNCONSUMED`;
- `new_state: CONSUMED`;
- `consumed_by_commit: c9fe3974753395ed343fed9e922c9c2ea695129b`;
- both durable evidence-ref names and exact peeled targets;
- the accepted candidate and acceptance artifact SHA-256 values;
- the exact independent acceptance verdict and reviewer identity already recorded;
- the reconciliation implementation date, implementer, independent reviewer, reviewed subject hash,
  and validation evidence;
- `replay_allowed: false`;
- explicit non-effects: no C0.3/Cycle-0 ratification, no authority adjudication, no runtime authority,
  no migration, no cutover, and no later-slice authorization; and
- a precedence statement that historical `UNCONSUMED` sentences describe their publication-time
  state and are superseded for current lifecycle queries only by this later content-bound record.

Historical authorization, incident, recovery, implementation-report, candidate, and acceptance
artifacts remain byte-identical. In particular, the independently reviewed acceptance artifact must
not be edited after review merely to modernize a temporal sentence. Current consumers must resolve
the latest valid lifecycle transition for the exact authorization ID and idempotency key, while
retaining all earlier states as audit history.

The consumption record must not be committed until both local evidence refs exist and validation
proves their exact peeled targets. Conversely, ref creation alone does not consume the authorization:
if the tracked consumption commit fails, the refs preserve evidence but lifecycle remains
`RECONCILIATION_INCOMPLETE` until a newly reviewed recovery authorization completes the additive
record.

## 4. Exact future authorization boundary

One future hash-bound reconciliation authorization may permit only:

### Git metadata writes

1. create annotated tag object and absent ref
   `refs/tags/aqos-evidence/c0.3/integration-c9fe3974`;
2. create annotated tag object and absent ref
   `refs/tags/aqos-evidence/c0.3/reviewed-head-d918a21a`; and
3. perform no other ref, index, worktree, configuration, reflog, branch, remote, or object mutation.

### Tracked-file writes

1. create
   `.agents/plans/aqos-refoundation-cycle0/C0.3-AUTHORIZATION-CONSUMPTION.md`; and
2. create one atomic commit containing only this new consumption record after independent exact-byte
   acceptance.

The authorization must bind:

- exact pre-execution `HEAD`;
- this design's SHA-256;
- both target commit IDs, parents, and trees;
- both exact absent ref names;
- the exact tag-message templates and tagger identity/time policy;
- the expected acceptance candidate and artifact SHA-256 values;
- the one-file tracked inventory;
- one named implementer and a different independent reviewer;
- a single-use activation ID, activation/expiry window, and no-replay rule; and
- an overlap check proving no other lane owns either ref or the consumption path.

Tag creation and the tracked consumption commit are two fail-closed stages under one authorization.
Recovery from a partial or pre-existing authorized ref may resume only by proving every existing authorized ref is byte- and
target-identical; it may never delete or replace a correct preservation ref as “cleanup.”

### 4.1 Stage recovery matrix

| Observed state | Lifecycle state | Permitted recovery |
|---|---|---|
| No tag objects, no refs, no record | `UNCONSUMED` | Start exact authorization from preflight. |
| Deterministic tag object(s) exist but neither ref exists | `UNCONSUMED` | Re-verify object bytes; retry the single atomic two-ref transaction. Unreferenced tag objects need no deletion. |
| Exactly one authorized ref exists and is exact | `RECONCILIATION_INCOMPLETE` | Preserve it; a newly reviewed recovery authorization may atomically create only the absent exact ref after validating both tag objects. |
| Both exact refs exist, no committed consumption record | `UNCONSUMED / EVIDENCE_PRESERVED` | Preserve refs; independently accept and commit the additive record under the active/recovery grant. |
| Exact record committed | `CONSUMED` | Never reset/delete/rewrite. Any factual correction is a new additive superseding record under new authority. |
| Any conflicting ref/object/record | `CONFLICT` | Stop; no force, delete, retarget, reset, or cleanup mutation. |

## 5. Threat model and controls

| Threat | Required control |
|---|---|
| Garbage collection deletes unreachable accepted commits | install verified durable refs before the next prune/GC; stop immediately if either object is already absent; claim only exact targets + locally reachable segment because the repository is shallow |
| Ref substitution or force-update | require absent refs or exact idempotent match; use old-value/CAS ref updates; prohibit force and deletion |
| Tag points to a tag, tree, or wrong commit | require peeled `^{commit}` equality plus exact commit parent/tree verification |
| Misleading tag message grants authority | freeze message fields and include `EVIDENCE_ONLY`; machine lifecycle truth remains the tracked consumption record |
| Hash ambiguity or collision claims | record repository object format, Git IDs, parents, trees, and independent SHA-256 artifact digests |
| Main-history rewrite to reconnect commits | prohibit merge, rebase, cherry-pick, replace refs, grafts, reset, branch movement, and commit-tree rewriting |
| Hidden replacement topology | reject `refs/replace/*`, grafts, shallow boundaries affecting either chain, or alternate-object ambiguity until independently dispositioned |
| Concurrent ref writer | preflight ownership, use atomic compare-and-swap updates, re-read targets after each update |
| Authorization replay | closed transition `UNCONSUMED -> CONSUMED`, exact idempotency key, `replay_allowed=false`, single-use activation |
| False consumption without accepted integration | require integration object/tree/parent, accepted candidate/artifact hashes, PASS artifact, and both evidence refs before publication |
| Historical evidence rewritten to remove contradiction | preserve all reviewed/historical files byte-for-byte; add a later precedence-bearing transition |
| Local-only preservation mistaken for backup | report `remote_publication=NOT_AUTHORIZED/NOT_VERIFIED`; require a separate explicit push and remote verification |
| Partial completion | expose `RECONCILIATION_INCOMPLETE`; never delete a valid preservation ref; require reviewed recovery for remaining stage |
| Reviewer self-acceptance | implementer and reviewer identities must differ; reviewer is read-only until its explicit final `PASS` |

### 6.2 Post-ref verification

For each tag:

- `git cat-file -t <ref>` returns `tag`;
- `git rev-parse <ref>^{commit}` equals the exact authorized target;
- `git for-each-ref` reports only the authorized ref names and tag objects;
- parsed tag content exactly matches the frozen template;
- the target commit's parent and tree remain exact; and
- `git fsck --no-reflogs --unreachable` no longer reports either protected commit as unreachable;
  no claim is made about unavailable ancestry beyond the frozen shallow boundary.

The reviewer must independently repeat these checks and compare the full ref inventory before
issuing `PASS`.

unchanged, and no merge/cherry-pick/rebase connected the historical chains.

## 7. Stop conditions

Stop without consuming authorization if any of the following occurs:

1. either protected commit or any frozen parent/tree is absent or mismatched;
2. current `main` no longer has exactly one parentless root at `a0bd5520...`, unless a revised design
   independently explains the changed topology;
3. either protected commit unexpectedly becomes an ancestor of `main`;
4. an evidence ref exists with a different tag object, message, type, or peeled target;
5. a replace ref, graft, shallow boundary, alternate-object source, or object corruption makes
   provenance ambiguous;
6. any unowned writer touches either authorized ref or the one tracked path;
7. the acceptance candidate/artifact digest or PASS boundary differs;
8. any command would require force, deletion, history rewrite, branch movement, network access, or
   modification outside the exact ceiling;
9. independent review is unavailable, recused, timed out, or does not end in exact `PASS`;
10. Tier 0, doc-link, diff-hygiene, or exact-inventory validation fails; or
11. the consumption record implies C0.3 ratification, Cycle-0 exit, authority convergence, runtime
    permission, migration, cutover, or downstream authorization.

## 8. Explicit exclusions

This design does not authorize:

- any Git ref mutation now;
- merge, rebase, cherry-pick, graft, replace ref, reset, force-update, or rewrite of `main`;
- deletion, pruning, repacking, garbage collection, or expiry of reflogs;
- staging or committing this design or any candidate implementation;
- modification of the 23 accepted C0.3 implementation paths;
- modification of historical authorization, incident, recovery, report, candidate, or acceptance
  artifacts;
- remote push/fetch, network access, deployment, Nix changes, service/process actions, database
  access, runtime hooks, traffic, or cutover;
- owner adjudication of the ten authority rows;
- C0.3/Cycle-0 ratification or Foundation/Cycle-1 implementation authority; or
- reuse of the consumed parent authorization for any correction or later slice.

The reconciliation is complete only when both evidence refs are exact and reachable, one independently
accepted additive consumption record is committed without rewriting history, and all operator-facing
status distinguishes implementation acceptance, authorization consumption, C0.3 ratification, and
remote evidence publication as separate states.
