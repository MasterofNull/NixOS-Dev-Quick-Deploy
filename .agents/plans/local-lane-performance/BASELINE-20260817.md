# Local lane baseline — 2026-08-17

Status: baseline
Owner: hyperd
Last Updated: 2026-08-17

**Goal (owner-directed):** offload more work to local → longer remote session windows + fewer token-limit
hits → longer collaborative work + monitoring. Measure the increase empirically, dogfooded.

## The metric that matters
**Local share of work × local reliability.** More offload only helps if local is DEPENDABLE — an
unreliable local lane forces remote retries, which burns the runway we're trying to save. So the lever is
reliability first, then share.

| Throughput | ~3–7 min / bounded task (leapfrog sequential) | measured this session |
| Capability (bench) | PENDING (bench-local-agent --quick running, APU slow) | prior Qwen3-35B: 82/85, tool_use 92 |

## Improvement targets (ranked by leverage for "offload more")
1. **Reliability — kill the ~11% failure tail** (biggest lever). The three modes are already understood:
   - Empty response → the enable_thinking/token-budget class (known fix pattern).
   - Backpressure reject → SOLVED this session: sequential leapfrog, never concurrent batch (codified in
     `feedback-local-continuous-slice-prep`). Enforce it in the delegation path so it can't recur.
   - Connection drop → add a bounded auto-retry (1 retry) on transient "Remote end closed".
   A dependable local lane is what lets us move more OFF remote.
2. **Share — grow local's slice** every cycle (prep, bounded single-file work, reviews) as reliability rises.
3. **Throughput** — bounded by the APU; leapfrog + right-sized tasks is the practical ceiling.

## How we prove it (the empirical loop — reuse existing instruments, no new admin)
- `bench-local-agent --quick` for capability (this doc's PENDING row).
- This log-derived success-rate + share (repeatable each cycle from `.agents/delegation/outputs/`).
- Delta per cycle: success-rate X→Y, share X→Y, failures-per-100-tasks down. That is the evidence that
  performance/capability increased — generated by doing the reliability dev, not by admin.

## Next dev slice
Fix the reliability tail (auto-retry on connection drop + enforce sequential-leapfrog in the delegation
path + confirm the empty-response guard), then re-measure success-rate against this baseline.
