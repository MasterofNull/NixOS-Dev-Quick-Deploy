## 1. What SSSF is (one paragraph, grounded)

A reusable **Claude skill** (`.claude/skills/sssf/`) that runs repeatable multi-agent SDLC
workflows on the principle **"agent proposes, code disposes."** The orchestration is
**deterministic Python** (an "ADW" script — Agentic Dev Workflow) that sequences named
**phases**; each phase is owned by either code or a single bounded agent
(planner / builder / reviewer / scout / documenter). Agents hand off **typed JSON
envelopes**; deterministic **gates** validate each phase's *claims* after it runs; on gate
failure the pipeline **re-prompts the same agent session with verbatim feedback** (bounded:
test loop ≤3, review loop ≤2). Everything streams to **SQLite (WAL) + JSONL** as it runs,
read live by a Vue visualizer. Its thesis: unstructured agent loops mean "almost nobody gets
the same result twice"; moving control flow into testable code makes runs **reproducible**.

## 3. Genuine gaps worth incorporating (scoped items — NOT authorized to build here)

The 4 ideas where SSSF is genuinely ahead for the **repeatable-production-workflow**
dimension (distinct from our research/exploratory agentic loop, which stays):

### G1 — Deterministic code-sequenced workflow lane ("ADW") alongside `aq-loop`
Their strongest idea. `aq-loop` is deliberately fluid/agentic (right for open-ended backlog
work). But for **repeatable, high-validation** workflows (e.g. the golden-task bank, release
pipelines, the PM-tracker regen), a **deterministic Python-sequenced pipeline** where control
flow is testable code and each stage is a bounded agent call gives reproducibility we
currently get only by post-hoc validation. **Scope**: a thin `aq-adw` runner that reads a
declarative phase-chain (YAML) + a role roster, calls one bounded agent per phase, and is
itself unit-testable. Complements, does not replace, `aq-loop`. Routes phases via Rule 17.
**Est**: medium (new runner + chain schema + 1 reference chain). Fits our cheapest-eligible
model (deterministic sequencing is code; only phase *judgment* is agent).

### G2 — Typed phase-handoff envelope + prompt substitution
Replace/augment free-form HANDOFF/PULSE hand-offs with a **schema-validated envelope**
(`status`, `summary`, `artifacts[]`, `notes_for_next_agent`) that the next phase's prompt
receives via substitution. We already have signed A2A in Foundation C — this is the
*non-security* dev-workflow analog. **Scope**: an envelope schema (`config/schemas/`) + a
substitution helper + wire into the G1 runner. **Est**: small. High leverage: makes
agent-to-agent handoff queryable + prevents "hallucinated prior work."

### G3 — Gate-fail re-prompt with preserved session context (bounded)
Make "re-prompt the same agent session with the verbatim failing gate output, ≤N times" a
**first-class contract** in the workflow runner (their test≤3 / review≤2). We have the retry
*budget* (Rule 6) but not the *preserve-session + inject-verbatim-gate-output* mechanism.
**Scope**: fold into G1's runner (retry = same agentId via SendMessage + gate-failure
payload). **Est**: small, depends on G1.

### G4 — Per-phase context-window-fill % + itemized cost in observability
Add **context-occupancy %** and per-phase reasoning-token cost to our telemetry/dashboard
(they surface window-fill % + hung-agent detection). We have token budgets; we don't surface
occupancy per phase. **Scope**: extend aq-event/telemetry projection + one dashboard card
field. **Est**: small. Directly serves "you cannot manage what you cannot measure."

## 4. Where we already exceed (do NOT regress toward their simplicity)

Confinement runner + CapabilityLease + epoch kill-switch (vs their file-DAC); dynamic
cheapest-eligible routing (vs static config); multi-agent fan-out + consensus + never-skip-
local (vs single-threaded cloud-default); NixOS declarative infra + activation gate (vs a
stamped skill); report≠record verifier + sealed oracles. Adopting G1–G4 must **not** flatten
these — the ADW lane is an *addition* for repeatable workflows, not a replacement of the
agentic/secure spine.

## 5. Recommendation

Incorporate **G1+G2+G3 as one coherent slice** (a deterministic `aq-adw` workflow lane with
typed envelopes + bounded gate-retry) and **G4 independently** (cheap observability win).
Sequence AFTER Foundation C's current live tier closes (R7 GREEN → C4) so we don't fork focus
off the security spine. Each becomes a normal PRD→freeze→cheapest-eligible-build→review cycle
under the standing rules. Net posture after adoption: **we match SSSF's reproducibility
discipline while retaining our decisive lead on security, routing, and multi-agent
collaboration** — i.e. parity captured and exceeded.
