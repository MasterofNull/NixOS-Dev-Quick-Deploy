# Coding factories: primary-source evidence ledger

Access: 2026-11-12 UTC (initial source retrieval approximately 05:11 UTC; recovered notes saved at 15:23 UTC). Scope: maintainers' current reachable documentation, not independent deployment experiments. Mutable documentation was not commit-pinned; this snapshot does not establish that every November 2026 product release is covered. Capability statements below are documented claims unless explicitly labelled inference. No cross-product benchmark ranking is supported.

| ID | Primary source | Bounded finding and limitation |
|---|---|---|
| CF-01 | [Claude Code agent teams](https://code.claude.com/docs/en/agent-teams) | Experimental shared tasks, dependency/claim coordination, mailbox and lifecycle hooks. Fixed lead and separate teammate sessions. In-process teammates are not restored by resume/rewind; stale work may need replacement or nudging. Persistent task records do not imply durable process recovery. |
| CF-02 | [Claude Code subagents](https://code.claude.com/docs/en/sub-agents) | Separate context, configurable tools/permissions and scoped memory; optional worktree isolation. Team conversion and shell-specific guards affect isolation. A worktree is a repository arrangement, not an OS security sandbox. |
| CF-03 | [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents.md) | Parallel threads with steering/closing and model/instruction configuration. They inherit parent sandbox and approvals; a readonly instruction does not create an independent permission boundary. Concurrent writes and token overhead require explicit coordination. |
| CF-04 | [Codex automations](https://learn.chatgpt.com/docs/automations.md) | Scheduled/event runs and results; desktop local work requires the machine/app available. Web runs do not retain a local worktree between executions. This is not public evidence of an arbitrary durable dependency graph or exactly-once side effects. |
| CF-05 | [Cursor cloud agents](https://cursor.com/docs/cloud-agent) | Isolated VMs, branches/PRs, environment setup, logs/screenshots and interactive takeover; work continues after disconnect. Network/admin permissions and hook stages matter. Persistent background execution alone does not prove restart replay or independent acceptance. |
| CF-06 | [Factory subagents](https://docs.factory.com/harness/subagents) | Background task handles, output/stop/resume, model tiers, scoped tools and inherited/limited autonomy. Invalid or blocked model configuration can fall back to parent; cost policy needs runtime receipts. |
| CF-07 | [Factory Missions](https://docs.factory.com/missions/overview) | Approved plans/features/milestones and Mission Control intervention; reviewer and flow-validation roles. Reliable validation depends on scriptable app dependencies and journeys. Documentation itself discusses accumulating errors and cost/parallelism tradeoffs. |
| CF-08 | [Factory Droid computers](https://docs.factory.com/droid-computers/overview) | Capacity-aware placement, waiting/resumption and resource telemetry. Sessions on a computer share CPU/memory/disk; instructed worktrees do not create independent OS isolation. |
| CF-09 | [Devin dynamic workflows](https://docs.devin.ai/work-with-devin/dynamic-workflows) | Deterministic Python orchestration, child sessions and structured results; recorded calls replay completed results and rerun unfinished work. Enterprise/admin availability matters. Replay does not make arbitrary external actions idempotent. |
| CF-10 | [Devin memory](https://docs.devin.ai/product-guides/memory) | Personal user/org memory in Git Markdown with source session/date and conflict handling. Personal memory is not team-shared and is excluded from automation runs. Retrieval is not evidence of beneficial or authorized weight training. |
| CF-11 | [GitHub Copilot agent risks and mitigations](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/security-governance-and-network-settings/risks-and-mitigations) | Branch-scoped workflow, logs and configurable scans/review; agent cannot approve/merge its own PR and humans retain acceptance. Some controls are configurable. A second model review does not by itself establish identity/subject independence. |
| CF-12 | [Gas Town repository](https://github.com/gastownhall/gastown) | Git-backed work/identity, Beads ledger, molecule checkpoints and specialized monitoring/merge roles. Maintainer-described architecture, not an independent audit of recovery correctness or claimed fleet scale. |
| CF-13 | [Overstory repository](https://github.com/jayminwest/overstory) | Runtime adapters, worktrees, SQLite mail/merge coordination, watchdog/checkpoint/handoff and fleet telemetry. Some specification/review steps can be skipped. Runtime guard equivalence and recovery safety are not independently established here. |
| CF-14 | [OpenAI Symphony README](https://github.com/openai/symphony) | Engineering preview for trusted environments; experimental Elixir reference implementation rather than evidence of a mature turnkey service. |
| CF-15 | [Symphony specification](https://github.com/openai/symphony/blob/main/SPEC.md) | Draft versioned WORKFLOW.md, tracker-driven dispatch, per-issue workspaces, concurrency/retries/reconciliation and optional observability. Restart reconstruction uses tracker/filesystem; no mandated strong sandbox, approval policy or general workflow engine. Worktrees are optional. |

Inference register: I-CF01 distinguishes a durable task ledger, restored context, replayed result, and idempotent external action. I-CF02 proposes requirement→dispatch→exact Git subject→tests→independent review→activation as the local parity target; these sources do not prove that whole chain for arbitrary deployments. I-CF03 treats independence as identity, authority and subject binding rather than prompt wording. I-CF04 requires memory provenance, tenant scope and held-out benefit before promotion. I-CF05 measures total orchestration/retry/validation/idle/operator cost per accepted outcome, not only token price. These are proposed engineering requirements, not externally benchmarked findings.

Unresolved: exact current release/commit inventory; independent recovery fault injection; permissions under every provider/runtime; genuine reviewer separation; end-to-end source-to-training authorization; comparable outcome/cost distributions. No public evidence in this bounded source set must not be rendered as an absent feature.
